# 高亮 → True Recall 卡片

用户说「把这（篇/个文件）的高亮做成 true recall 的卡」「高亮转成卡片」「用这个 skill 处理 XXX」时走本 skill。

> **本文是「高亮转 True Recall 卡」的唯一权威源。** 两层 MEMORY、日志只写一句话 + 指向本文，不复制正文。
> **另两个卡源（只指路、不复写）**：`⭐`/`⏳` 标题 → basic 问答卡见 **`heading-to-true-recall`**；把库里**已存在的 suspend basic 卡**就地转成 cloze 挖空卡见 **`basic-to-cloze-true-recall`**（它**不读源笔记**，挖空位置只认卡面 `Back` 里手画的 `==`，产出的 Extra 一律是标题链接）。

## 0. 铁律（先读）

1. **只处理用户点名的那个文件**（任务范围纪律）。不主动扫全库、不顺手处理同系列其他文件。
2. **默认走插件自带 Local API，不需要退出 Obsidian**（服务器就跑在插件里）。只有**直接改库**（`--sqlite` 路线、`tr_db_cleanup.py`）才要求"插件已停"——**"插件已停"≠"必须退出 Obsidian"**：设置里禁用 True Recall 同样触发 `onunload → coreApp.shutdown() → cardStore.saveNow()`，与退出 Obsidian **走的是同一条落盘路径、安全性完全相同**（见「6. 已知边界」）。⚠️ **AI 想自己启停插件，唯一的路是 QuickAdd 用户脚本**（`app.plugins.disablePluginAndSave / enablePluginAndSave`，见本机现成的 `Scripts/fakelink开关.js`）；Local API 的 71 条路由里没有这个能力，且禁用后 `localApi.stop()` 会形成自锁。
   **但清孤儿 note 根本不需要停插件**：本机已做成 QuickAdd 宏 **`TR清理`**（脚本 `<vault>\Scripts\truerecall清理.js`），在 Obsidian 运行时直接调插件自己的 store 软删并让它自己落盘 —— 不停插件、不碰磁盘文件、不依赖外部程序，且可由 AI 用 `obsidian://quickadd` 主动触发。用法见「3. 执行流程」第 9 步「路线 A」。
3. **先预览、后落盘**。脚本不带 `--apply` 只打印，不写任何东西。给用户看过预览再执行。
4. **`==高亮==` 是用户的人工专属标记**：本 skill 只读取它，绝不新增高亮（详见 `vault-write-discipline` 第 4 条）。辖域 = **vault 笔记正文**；本 skill 写入插件卡面字段（Text/Extra）时按挖空格式包 `==`（内容外套 `==…==`、hint 包 `==`）属卡面格式、不受此限。
5. **必须写 `source_text`**（默认就写）。不写的话复习面板上"跳回原文"点了没反应——插件的跳转逻辑开头就是 `if(!card.sourceText) return`。
6. **⚠️「直接写 SQLite」路线已被实测证伪**：写进去的卡在插件下次启动 / 同步时被 `softDeleteWithCascade` 全部级联软删（`notes` 保留、`cards` 的 `deleted_at` 全被填上 → 浏览器里看不到）。**默认路线已改为插件 Local API**，`--sqlite` 只作兜底。判定导入是否真的发生：查 `cards where deleted_at is null`。
   **⚠️ 本条只针对「新增卡」（INSERT）方向（2026-10-02 审查补）**：**软删（UPDATE `deleted_at`）方向是另一回事**——直写软删**可以持久**，但**必须同条 `UPDATE` 里把 `updated_at` 抬到远未来**（现 + 10 年毫秒），否则会被应用同步的 upsert 守卫（`excluded.updated_at > notes.updated_at` 为真时整行覆盖、把 `deleted_at` 抹回 NULL）**回滚**。详见「6. 已知边界」的删卡条。别把本条读成"任何直写都无效"。
7. **⚠️ 幂等有五个致命细节**：① 比较 `fields_json` 前**必须归一化**（插件落库是紧凑 JSON `{"Text":"…"}`，Python `json.dumps` 默认带空格 `{"Text": "…"}`，**解析后相等、字符串不等**）；② 幂等查询**必须走 `/query`（插件自己的 DB 连接）**，直接开 SQLite 只读连接会因插件**落盘延迟**读到旧状态，建完卡马上重跑会整批重建。两个都踩上就是"每跑一次多一倍"；③ **`/query` 默认关**（`apiEnableSqlQuery=false`），脚本已自动降级到 `GET /notes/cards?source_uid=…` —— 降级后幂等只比对本笔记的卡（`/query` 是比全库），同一段高亮在两篇笔记里都有时会各建一张，这反倒更正确；④ **降级路径返回的不是原始字段**：`question` 是**卡面展示态**（`{{c1::x}}`→`[...]`）、`answer` 是**整面**（渲染 Text + `<br>` + Extra），拿它们当 cloze 的 `Text`/`Extra` 比键**永远不相等** ⇒ 复跑又建一批。修法与源码细节见 1 节「v2.5.0 的两处破坏性变更」第 2 条；⑤ **`GET /cards/:id` 返回的是扁平对象**（`sourceText` 直接在顶层，**没有 `{ok,data}` 包一层**）⇒ 写成 `(one.get("data") or {}).get("sourceText")` 会**恒为空串**、`source_text` 幂等键整条失效；而同一批卡 `Extra` 里的 `line=` 会随 frontmatter 写入整体后移 ⇒ **两个键同时失效 = 每复跑一次多一整批**。修法 = `(one.get("data") or one).get("sourceText")`（兼容两种形态）。**教训：降级路径上每一个「该取哪一层」都要拿真实响应核对**，别照抄同族脚本里别的路由的写法 —— `/cards`（POST）确实带 `{ok,data}`，`/cards/:id`（GET）不带。
   判据不变：**复跑必须打印「新增 0 张」**，否则立刻停手查键、不要继续跑。
8. **`--apply` 跑完立刻复跑一次**，必须看到「新增 0 张 / 已存在跳过 N 张」才算幂等生效。没有复跑验证就别说"建好了"。
9. **⚠️ 删卡会"连带"删 —— 机制已挖到源码级**。`DELETE /cards/:id`、`POST /cards/bulk-delete`、复习界面 `Shift+1` / 右键 Delete card、卡片面板的删除，最终都走同一条 `Mi` 命令 → `deleteBatchWithCascade(ids)`；**实际删除集合 = 传入每个 id 的 `collectCascadeDeleteIds(id)` 之并**。单个 id 只贡献三样：
   ① **它自己**；
   ② **仅 cloze 卡**（`cardType==="cloze"` 且有 `clozeTemplate` + `sourceUid`）→ **同源笔记 + 同 `clozeTemplate` 的全部活卡**（`getClozeSiblings`）。⚠️ **但本 skill 经 `POST /cards` 建的卡不带 `clozeTemplate`**（处理函数只传 `noteTypeId / fields / sourceUid / sourceText`，SQLite 的 `cards` 表也没有该列 ⇒ 恒为 `undefined`）⇒ **这一支对本 skill 建的卡整个不触发**；带该字段的只有手工建卡 / Collect / Anki 导入 / 走过 `updateClozeTemplate` 的卡。集合口径是「**同源笔记 + `clozeTemplate` 逐字相同**」，**没有"块"这一层概念**；
   ③ **`reverseOf` 为空时**（cloze / basic / **图片蒙板**都为空，只有 reversed 卡才带）→ **同 note 里任意另一张 `template_ord` 不同的活卡，SQL `LIMIT 1`**。**顺序不保证、不可控**。
   **实操后果（按条对照）**：
   - **想"只删一张、留另一张"做不到**（⚠️ **对图片蒙板与带 `clozeTemplate` 的卡成立，对本 skill 经 `POST /cards` 建的 cloze/basic 卡不成立**）：②③ 任一命中都会带走别的卡。本 skill 自己建的卡是**一卡一 note、且无 `clozeTemplate`** ⇒ ②③ 都查不到目标，**删一张只删它自己**（实测某笔记 20 张 → 删 1 张 basic → 19 张、cloze 两张原封不动，见 `heading-to-true-recall` 铁律 6）。此前记录的"图片蒙板 2 卡 note 删一张即两张全没、再删第二张 404"，正是第 ③ 支，**不是**"note 级联"。
     **★ 但「想去掉图片蒙板里的某一题」有精确解 —— 回编辑器删掉那个框再保存**：编辑器删框就是 `sX()` = `{...t, regions: t.regions.filter(r => r.id !== e)}`，**纯 filter、不重排 `groupKey`**（只有新画框走 `qA()` = 当前最大值 + 1），所以剩下的框保留原编号（允许空洞）；保存走 `reconcileImageOcclusionCards` 按 `templateOrd` 对账 —— 保留交集、软删多余 ⇒ **删哪个框就精确删掉哪张卡**，且全程**不经过 `Mi` 命令**、不连带。想删一道题就走这条，别用删卡。
   - **图片蒙板多组卡（≥3 张）有坑**：复习界面 `Shift+1` 删一张会**连带删掉同 note 的另一张**（③ `LIMIT 1`），剩 `N-2` 张、且掉哪张不可控。⇒ **要么整条清、要么别在复习界面单张删**。
   - `Suspend` / `Bury` 是同一套"组"语义（`getGroupSiblingIds` 三分支与 `collectCascadeDeleteIds` 完全同构）→ 对图片蒙板卡同样是"一次动两张"。
   - **浏览界面（card browser）并不例外**：全插件只有一处删除实现 —— 浏览器选择工具栏的 `Delete` 就是 `new Mi(选中的 id 数组)`（组件 `hne`），与复习界面 / 侧边面板 / Local API 是同一个命令类，所以**浏览器里单张删照样连带**（唯一不连带的情况：该 note 只有 1 张卡，③ 支查不到 `template_ord != self` 的行）。但它有复习界面比不了的优势：**一行一张卡**（IO 多组 = 多行 `Image occlusion 1/2/3`），**把整条 note 的卡全选再删 → 并集正好覆盖整条 → 干净可控**。两个坑：① 跨 note 混选会放大（选 A 一张 + B 一张 → 实删 4 张）；② `Select all N` = "当前查询命中的卡"，筛选 / 搜索把某条 note 的卡拆到查询外时，仍会从查询外把兄弟拉进来，**不等于安全**。
   - **「删」与「暂停/埋葬/忘记」的可控性不同**：浏览器工具栏的 `Suspend` / `Unsuspend` / `Forget` 走 `bulkSuspend` / `bulkForget(选中的 id)`，**只动选中的卡、不连带**；而复习界面的 `Suspend` / `Bury` / `Forget` 走 `getGroupSiblingIds`（IO 同构 → 一次动两张）。⇒ 一句话判据：**「删」在哪个界面都一样会连带；「暂停/埋葬/忘记」只有复习界面会连带。**
   - **清掉某条笔记的全部卡，用 `POST /cards/remove-from-note {source_uid}`**（把该 uid 的全部卡 id 一次性交给 `Mi`，可撤销）；**`removeFlashcardsByIdsWithDetails` 天然是"清整条 note"的正确粒度**，别逐张删。
   - **任何删卡路径都不会删 `notes` 行**（软删 `notes` 全插件只有两处：关闭 `note-review` 的 `disableNoteReview`、数据完整性修复 `Ah.repair`；**硬删 `DELETE FROM notes` 全插件 0 处**）→ **删完必然留空壳 note**，这是"完整删卡"要补第二步的原因。
   - **⚠️ 插件自带的 `Check integrity` 替代不了 `TR清理`**：它查的是**数据库指针悬空**（卡指向的 `notes` 行不存在等），**空壳 note 沾不到**；而且它只在**库第一次加载时静默自动跑一次**（`meta.integrity_checked` 标记，无提示无备份），之后永不再自动跑。三类「孤儿」的判据 SQL、动作、备份 / 撤销差异 → IO 参考 §十一.4。
10. **`Extra` 默认写成"一行链接"**（`[《笔记名》·第 N 块](obsidian://adv-uri?...&line=...)`），这是用户点名要的"一键跳回原文"；改存量卡片用 `--relink`，**不要重建卡**（重建会重置调度并攒孤儿 note）。
11. **任务收尾必须做"残留自检"并如实报告（用户定）**。本 skill 每跑一轮都可能攒下两类残余：① 库里的**孤儿 note**（只软删 card、note 留成空壳）；② `<vault>\临时\` 里的**中间文件**（`.apkg` / `.csv` / `导入.txt` 等）。收尾时**只读**各查一次，把清单摆给用户，**默认只报告、不擅自删**。用户说清之后的标准动作：**跑 QuickAdd 宏 `TR清理`**（不停插件、不关 ob、只软删孤儿 note 并让插件自己落盘，且**AI 可用 `obsidian://quickadd` 自行触发**，用户已明确授权，见第 9 步路线 A）。临时目录里的中间文件由 AI 备份后删除。

### v2.5.0 的两处破坏性变更（**取代此前"只绑本机、无鉴权"的旧口径**）

1. **Local API 必须带 token**。鉴权在**路由匹配之前**做：`GET /status` 无头实测 **401 unauthorized**，带 `x-true-recall-token`（或 `Authorization: Bearer <token>`）才是 200。token 由插件生成、存 Obsidian localStorage，设置页 Local API → Copy token 可取。`hl2tr.py` 三级取法：`--token=` → 环境变量 → `<skill目录>/.local-api-token`。
2. **`POST /query` 默认关**。新设置项 `apiEnableSqlQuery`（默认 `false`），关着时带 token 也返回 **403 `sql-query-disabled`**。`hl2tr.py` 已自动降级到 `GET /notes/cards?source_uid=…&limit=200`（SQL 写死 `c.deleted_at IS NULL`，只返活卡）。⚠️ 该路由**默认只返 50 条**，一篇笔记能到 50+ 张卡 ⇒ `limit` 必须显式给；⚠️ 降级后幂等**只比对本笔记的卡**（`/query` 是比全库），同一段高亮在两篇笔记里都有时会各建一张 —— 这才是对的。**不必**去开那个开关。
   ⚠️⚠️ **降级路由返回的不是原始字段（实测血案，`hl2tr.py` 已修）**：它的 `question` 是**卡面展示态**（`{{c1::x}}` 已渲染成 `[...]`）、`answer` 是**整面**（= 渲染后的 `Text` + `<br>` + `Extra`）。把它们直接当 cloze 的 `Text`/`Extra` 比幂等键 ⇒ 永远匹配不上 ⇒ **每跑一次多一整批卡**（实测同一篇连跑两次 `--apply`，库里 6 张、3 条内容各重复一份；`--relink` 同因每次报"需改 N 张"）。正解两条并用：① `Text` 侧做**渲染归一化**（`re.sub(r"\{\{c\d+::(.*?)\}\}", "[...]", text, re.S)`）、`Extra` 侧从 `answer` 里按**最后一个 `<br>`** 切尾段并校验开头是 `[《`/`《`（切不出就正则找行链接兜底）；② 更可靠的是逐张 `GET /cards/:id` 取 **`sourceText`**（块原文、含 `==`）与本地块逐字比。脚本同时用两套键，**命中任一即跳过**。⚠️ 另有一处同族坑：`GET /cards/:id` 是**扁平对象**（`sourceText` 在顶层、**没有** `data` 包装），必须写 `(one.get("data") or one)`，否则 `SourceText` 恒空 ⇒ 详见铁律 7 ⑤。

### v2.5.0 的重构把并组守卫打断了（⛔ 该守卫已于 2026-10-12 退役，**本节整节为历史留档**，不是可执行的修复记录）

- **现象**：点 `All` 保存后库里出**多张卡**（本该 1 张），而 `.true-recall/tr-io-autogroup.log` 里**一条 `[并组]` 都没有**。
- **根因（源码级）**：v2.5.0 把 `flashcardManager` 拆成「门面 + 子对象」，编辑器保存那条链**整条绕开门面** —— 编辑器调 `updateImageOcclusionNote` → 门面转 `imageOcclusion.updateImageOcclusionNote` → 内部 `this.updateFields` 是**构造时注入的箭头函数**，最终落到 **`noteMutation.updateNoteFields`**（新建同理落到 `noteCreation.createNote`）⇒ 旧守卫只包门面的 `fm.updateNoteFields` / `fm.createNote`，**一次都不会被调到**。

- **⚠️ 教训（比这次补丁更值钱）**：**插件大版本重构后，「门面方法还在」不等于「调用链还经过它」**。复核这类「包裹式补丁」必须**从事件源头那端顺着往下追**，把每一跳的 `this` 落到哪个对象写清楚；只 grep 方法名还在就下结论，会漏掉「换了宿主对象」这种整链失效。

⚠️ 配套的一条硬规矩：**想「改某一条已有卡」时，一张图只能用「编辑」入口，不能再点一次「制作蒙板」**（⚠️ 限定在"改"的语境；**故意要再加一道题**时重复制作恰恰是正解 —— 见上条）。add 模式无条件新建 note（保存回调 `if(tt){update}else{create}`，`tt`=`noteId` 只在 edit 模式有值；全插件无按图片路径查重、也无"已有卡"提示），且初始画布固定为空定义（`cee(t)` 非 edit 时返回 `Lm("solo")`，不读旧 note）⇒ 误用重复制作 = **静默多出一整套重复卡**。原生 IO 按钮与 `TR制作蒙板` 同形，都踩。详见 IO 参考 §十一.5 第 8 条。另：**同名图在同篇笔记贴两次**（**或对同一处重复制作 N 次**，二者等价，见 §十一.5 第 10.1 条）在删卡层面等价于改名（各成独立 note、删卡不连带）；按 basename 取行的地方现在只剩「跳到原图」（`findImageLine` 取**最早那处引用**，本库工作流里正文那张在前、正合意）。详见 §十一.5 第 9 条。

## 2. 知识块规则（本 skill 的核心口径）

**一个知识块 = 一张卡 = 一个 True Recall note；块内所有高亮统一编号 `{{c1::}}`。**
所以块内有几个高亮，复习时就是同一张卡一次挖掉几个空，不拆成多张卡。

块边界（默认口径，实现见 `scripts/hl2tr.py` 的 `build_units`）：

1. 空行、标题行（`#` 开头）、代码围栏（``` / ~~~）→ 硬边界，不属于任何块；**代码块内的高亮忽略**。
2. 列表项行（`- ` / `* ` / `+ ` / `1. ` / `1) `，**容忍 `1.**粗体**` 这种无空格写法**）→ 未缩进的**每行独立成块**。
3. **缩进归属（广哥定，默认开）**：**任何行首带缩进的行**（列表子项、缩进续行、缩进引用、缩进表格……不论几级）**一律并入上方最近的「未缩进行」所在块，不另起一块**；多级缩进也一路归到同一个父块。**父行自己没高亮、只有子行有高亮时照常合并**（父行文字当上下文一起进卡面）。`--no-indent-merge` 可关掉，退回「缩进子项也算独立块」的旧行为。
   ⚠️ 口径切换 = 结构性变化，重建正路（实跑定稿）：`POST /cards/remove-from-note {source_uid}` **整篇清空** → 重跑建卡 → `TR清理` 宏收掉空壳 note。**`--prune` 不作数**：它只在 `--sqlite` 路线生效、且 SQL 写死 `created_via='import'`，而走 Local API 建的卡 `created_via='claude_code'`，一条都清不到（只会平白多建一批重复卡）。
   ★★ **重建前必须先跑「逐块安全闸」——否则会静默冲掉手工改过的卡**：脚本 `tmp\tr_rebuild_safety_check.py`（已按用户级「辅助脚本用完即清」清理；不在就照本条做法就地重写一份，改 `FILE` 即可）。做法 = `import hl2tr` 后调 `build_units/build_blocks/block_cards` 现算出「源笔记会长成什么样」，再与库里该 uid 的活卡**按 `Extra` 里的「第 N 块」对齐逐块比 `Text`**。
   判据三类：① 只在库里 / 只在源笔记的块（增删卡）；② **Text 有差异的块 = 卡面被手工改过（或源笔记改过），重建会二选一丢一边**；③ 只有 `Extra` 差异的块 = 行链接 `line=` 过期（通常因为源笔记在某块之前插了行，导致其后所有块 `line=` 偏 N）—— 重建**会修正**它，这往往是重建唯一实打实的好处。
   **结论**：为了让某一块可复现而**整篇重建**，性价比可能为负 —— 先算清「丢几张手工改过的卡 + 清几次复习记录」再决定；只补 `==` 让「下次重建时长得出正确挖空数」往往就够了。
   判据（切缩进归属那次实跑）：3 篇清空 171 张 → 重建 157 张 → 复跑 `新增 0 / 跳过 157` 才算成。
   **离线自测**（改 `build_units` 后必跑，不需要 Obsidian）：`python scripts/test_hl2tr_indent.py`，8 项——父+子合并 / 父无高亮 / 多级缩进 / 平级不合并 / 空行切断 / 标题硬边界 / 段落+缩进续行 / `--no-indent-merge` 回退。
   **加粗失效自测**：`python scripts/test_hl2tr_wj.py`（需 `markdown_it`，托管 venv `binaries\python\envs\default` 里有）——场景 × 字符串层 + 渲染层，含两条**真实数据回归**（教育学 207 的 `=="组织起来的教育内容"归斯宾塞(内容说)==` 与 `=="预期的学习结果"归泰勒(目标说)==`），外加「**只包 `==` 不加 WJ 会全部失效**」的对照与「**`==` 内侧 WJ**」的 4 条断言（引号 / 括号开头、`$A$`、纯文字不加、尾句点）；没装 `markdown_it` 时自动只跑字符串层。
   **标记钩子自测**：`python scripts/test_hl2tr_cloze_mark.py`（同样需 `markdown_it`）——字符串层 + 渲染层（模拟阅读视图先把 `==x==` 换成 `<mark>x</mark>` 再渲染），断言四件事：① 挖空内容渲染成 `<strong>⁠<mark>…</mark>⁠</strong>`（钩子真的包住文字）；② 同卡里用户粗体只有 `<strong>`、没有 `<mark>`（CSS 不会误染）；③ 去掉 WJ 后 `**` 开不了、星号字面显示；④ 去掉 `==` 后只剩 `<strong>`（证明 `==` 是唯一钩子）。
4. 引用行（`>` 开头）→ 连续引用行合并成一块（未缩进的那一行为准）。
5. 表格行（`|` 开头）→ 未缩进的每行独立成块。
6. 其他非空行 → **连续多行合并成一块**（遇上面任一边界断开）。
7. **跨行高亮**（`==` 在某行开、后面的行才合）→ 把跨越的所有块合并成一块。

**字段口径**：

- `Text`（卡面/正面）= 块原文，`[[wiki 链接]]` **原样保留**，只把 `==x==` 换成 `{{c1::x}}`；已含 `{{c` 的块跳过，避免重复包裹。**同行若跟有 `%%提问%%`，则出 `{{c1::x::提问}}`**（⛔ 2026-10-12 起提问**不再包 `==`**，改走官方原生黑字，见 `mark_hint()`）。
  **挖空内部：文本格式全部清掉，只留纯文字**（2026-09-20 广哥定，由旧的「只去加粗」升级）。范围 = `**` `__`（加粗）、`*` `_`（斜体）、`~~删除线~~`；删完把多余空格压成一个。
  **⚠️ 两个例外（广哥 2026-09-20 补定，一律原样不动）**：① `$…$` 行内公式整段保留（公式里的 `_` 下标、`*` 乘号是数学内容，清掉就毁了）；② **`` `行内代码` `` 与 HTML 标签（`<b>` `<sub>` …）原样保留** —— 代码是内容不是格式（`` `file_name` `` 的下划线是标识符），HTML 标签删了丢语义。实现上先把公式与代码抠出来占位、清完再原样还原。
  为什么必须清：① 插件渲染"揭示答案"时自己会把挖空内容包成 `**...**`（**函数随版本变**：≤2.7.0 是 `ux()`、**2.7.1 起是 `px()`**，再早 v2.5.1 是 `zS()` / `rI()` 两条路径；**都硬编码这对 `**`、无任何开关** ⇒ **加粗是插件施加的、与用户写不写 `**` 无关**，纯文本照样被包），叠上用户写的 `**` 就是 `****内容****` → 嵌套 `<strong>`，且标记一旦不成对就会把字面 `**` 显示出来；② 更根本的是这些标记和脚本补的 `==` 高亮叠在一起时，卡面**经常渲染坏**（广哥原话：「不然后面内容高亮的时候经常有格式渲染问题」）。⚠️ 那对 `**` 是**渲染期现拼**的、拿本地补丁改掉它会随插件升级被打回（2026-09-20 晚打过、2026-09-29 已弃用改走 CSS）⇒ 本节这条清理规则**仍然保留**（"挖空内容里不留格式标记"的口径不变）。
  实现 = `hl2tr.strip_inline_md()`（`cloze_fill()` 在包 `==` **之前**调用；⛔ 2026-10-12 起默认不包 `==`，**但清格式照常执行**；第三段提问走 `mark_hint()`，同一把尺子）。`--keep-cloze-bold` 可关掉整个清理（含公式保护一起走）。
  **注意这里的「清格式」指的是「卡面文本里别再写 `**` 这类标记」——脚本自己别写，但广哥手写的照留**。⛔ **2026-10-12 起补丁停用** ⇒ 挖空恢复官方默认粗体（与本条清理不冲突：清理管的是**脚本不写**标记，粗体是插件施加的）。⇒ **广哥在卡面里手写的 `**` / `==` 一律正常生效**。⚠️ **WJ 仍必须留着**（默认开）：它护的是**插件那对 `**`**（`**` 会踩 flanking、露字面量），与 `==` 无关 —— 见下方「外层 WJ」。
  注意：**只清卡面，不动 `source_text`**。
  **⚠️ 光清掉 `**` 还不够** —— 实测全库约 **6.3%** 的挖空答案面加粗会失效、星号字面显示。根因是 CommonMark 的 **flanking 规则**：插件那对 `**` 要能「开」，要求紧跟着的字符不是空白、且（不是标点 或 前一个是空白/标点）；「闭」同理。⇒ **内容首尾是标点、外侧又紧贴文字**时就开不了 / 闭不了，两种典型：`若**$A$**经`（内容以 `$` 开头、前贴中文）、`是**重要。**在`（内容以 `。` 结尾、后贴中文）。
  **修法（默认开）**：在挖空**内容两端各插一个 Word Joiner `U+2060`**（`scripts/hl2tr.py` 的 `WJ` 常量）。它是 Cf 类，**既不算空白也不算标点**，`**` 就永远能开能闭；且不可见、落在 `$…$` 之外（不干扰 MathJax）。`--no-wj` 可关。**（这是「外层 WJ」；内容首尾是标点时还要在 `==` 内侧再补一层，见下方 `==` 那条。）**
  ⚠️ 它只加在**内容**两端，`source_text` 与 hint 都不加 ⇒ **幂等键（`_render_cloze` 后的形态）不变**，改完不会重刷整批卡；但**已建的旧卡不会自动带上**，要补就走 `POST /cards/:id/update {question: 带WJ的Text, answer: 原Extra}` 逐张改。
- **⛔ 挖空内容再包一层 `==…==`（2026-09-17 广哥定；**2026-10-12 起默认关闭**，要开得显式加 `--cloze-mark`）** —— 下面整段自 2026-10-12 起只作历史留档。
  为什么**当初**需要：插件给挖空内容加的那层加粗与用户自己画的 `**粗体**` 在 DOM 上**分不开**，CSS 想「只把挖空换个颜色」就必然误染——本库 157 张 cloze 卡里 **48 张（30%）** 卡面含非挖空粗体（`→ **历史性**`、`是**杜威**` 等），一染全黄。包上 `==` 就有精准钩子。**⛔ 2026-10-12 起：不再包 `==`，卡面完全走官方原生。**
  ⚠️ **`==` 标记在内、WJ 在外**，顺序不能反 —— `**==…==` 里 `**` 后面紧跟的是 `=`（Unicode 标点），夹在文字中间**开不了**。两者**绑定**：只包 `==` 不加 WJ，5 个场景**全部失效**；`main()` 已加保护，`--no-wj` 会自动把 `==` 一起关掉并打 ⚠。
  ⚠️ **WJ 还要再放一层「`==` 内侧」（默认开）**：内容**首/尾是标点或符号**时（`=="…"归斯宾塞(内容说)==`、`==$A$==`、`==《礼记》==`），`==` 自己也会踩 flanking ⇒ 左右标记开不了 / 闭不了、**露成字面 `==`**。修法：`is_edge_punct(ch)`（`unicodedata.category(ch)[0] in ("P","S")`）判定首 / 尾字符，是标点就在 `==` **里侧**再补一个 WJ ⇒ 最终形态 `⁠==⁠内容⁠==⁠`（**外层两个 WJ 给插件那对 `**`，内层两个给 `==` 自己**；内容首尾是普通文字时只加外层）。幂等：看是否已以 `WJ=="` 开头。
  幂等：内容首 / 尾已是 `=` 时不重复包（`==A===` 会解析坏）；`==` 只进第二段，`_render_cloze` 只吃第三段 ⇒ **幂等键同样不受影响**。
  **⚠️ 第一版用 `<span class="tr-cloze">`，卡面上实测无效**（源码级查明）——卡面不是 `MarkdownRenderer` 渲染的，而是 **Obsidian 的 CM6 编辑器（实时预览）**：插件 `Oa` 组件用 `EmbeddableEditor`。由此两条：① 实时预览里 `**x**` 渲染成 `<span class="cm-strong">`，**不是 `<strong>`**（所以「染 strong」从一开始就不可能生效）；② 行内 HTML 按**单个标签**逐个走 `HtmlWidget`，开 / 闭标签被拆成两个孤立 widget，开标签单独清洗后自动闭合 ⇒ 只剩**空 span**，文字落在它外面。改用 `==` 后：实时预览 `span.cm-highlight`、阅读视图 `<mark>`，两种模式都有钩子。
- `Extra` = **卡面最后那行的可点行链接**：显示文字是 `《笔记名》·第 N 块`，目标是一个 `obsidian://adv-uri?...&line=<该块起始行>` 链接（由 FakeLink 接管点击 → 直接打开源笔记并定位）。详见「5.5 节」。`--plain-extra` 可退回纯文字。
- `source_text` = **该块在笔记里的原始文本（含 `==`、含链接、含行首缩进）**。与手建卡完全对齐：用户手建那张卡的 `source_text` 存的就是 `==**行动研究**==` 这种含 `==` 的原文。**不要去掉 `==`**，否则 `indexOf` 找不到。

> **卡面里的 `[[...]]` 链接不是错误、更不是装饰**：插件用 `MarkdownRenderer.render(app, markdown, el, filePath=sourcePath)` 渲染卡面，`filePath` 传的就是源笔记路径，所以 `[[xxx.pdf#page=N|pdf]]`、`[[xxx.mp4#t=N|视频]]` 能正常解析、点击可跳。**出卡时必须保留链接原文**（用户明确定调）。

## 2.1 行内提问 `%%…%%`（广哥定，唯一权威源）

**一句话**：`%%提问%%` = **它前面最近那一个** `==高亮==` 的挖空处显示内容；**必须同行**才生效。⛔ 2026-10-12 起显示出来的提示语**不再包 `==`** ⇒ 问题面回到插件原生的黑字 `[提问]`（此前 2026-09-19~2026-10-11 期间是 `[==提问==]` 黄底）。

规则（实现在 `scripts/hl2tr.py` 的 `plan_cloze()`）：

1. **只在同行生效**：注释与其归属的高亮必须在同一行（判据 = 注释起始行 == 高亮结束行，跨行高亮按结束行算）。**单独成行的 `%%`、或同行前面没有高亮的 `%%` → 不生效**，在卡面里**原样保留**，预览时列进「未归属」清单供人工核对。
2. 归属**该行内它前面最近**的一个高亮；那个高亮若已有提问，再往前找同行的下一个。⇒ 一个高亮最多一个提问，一行里 `==A== %%Q1%% %%Q2%%` 的 `Q2` 会落进未归属。
3. 被消费掉的注释**从卡面 `Text` 删除**（内容已进第三段，留着会重复），连同它左侧紧邻的空格一并吞掉；**但右侧紧跟 `[`／`!`／字母数字时回填一个空格**。⚠️ 广哥报过「题面粘连」：`==**组织策略**== %%学习策略%%[[x.pdf#page=72|pdf]]` 这种写法里注释与链接之间**本来就没有空格**，两处空白一起吞掉后卡面成了 `[学习策略][[x.pdf#page=72|pdf]]`，`GS()` 渲染成 `[学习策略]` 紧贴链接别名 `pdf`。回填**只针对会粘住的字符**：`==A==%%Q%%.`（句点）、`}}经`（中文）这类不回填，免得凭空多空格。**⚠️ 2026-09-19 追加：回填的那一个空格只解决「粘连」；`}}` 与紧邻 `[[` 之间的间距由收尾的 `norm_link_gap()` 统一补成**两个空格** —— 只一个空格时，问题面上的 `[hint]` 会被解析成**链接文字**（广哥原话「把学习动机变成链接了」），两个空格才正常。**⚠️ hint 拼进方括号自 2026-09-17 引入占位符起就如此 ⇒ 这是**老问题**（全库 43 处里 17 处是老卡），语义 hint 被包 `==` 后更显眼。只规范 `}}` + `[[`，`![[` 嵌入形态按广哥 2026-09-19 指令**不动**（实测全库 0 处）。全库 43 处已同步、复跑待改 0。
4. **`source_text` 保持块原文不动**（逐字含 `%%`）——它是 `indexOf` 的定位坐标，动了就跳不回去。
5. `--no-hint` 可整篇关掉，退回旧行为（`%%` 一律原样留在卡面、挖空**也不填**默认占位符）。
   ⚠️ **没有 `%%提问%%` 的挖空会被填上默认占位符 hint**（`DEFAULT_HINT`，⛔ 2026-10-12 起值从 `::==⁠...⁠==` 改为裸 `::...`）⇒ 问题面显示成插件原生的裸 `[...]`（**不再是黄底三个点**，黄底那套判据随 CSS 片段一并于 2026-10-12 删除）；**有 `%%提问%%` 的挖空同样不再包 `==`**（2026-09-19~2026-10-11 期间是 `::==提问==`）⇒ 问题面是黑字 `[提问]`。两条来源样式统一（都是原生）。⚠️ 第三段(hint)属**幂等键**的一部分：改规则必须**连库一起改** —— 2026-10-12 这次就是用 `scripts/tr_unwrap_cloze_eq.py` 批量 `POST /cards/:id/update` 洗的（156 张、保调度）。
6. **离线自测**（改规则后必跑，不需要 Obsidian）：`python scripts/test_hl2tr_hint.py`，**71 项**（2026-09-19 新增「语义 hint 包裹」11 项 + 「`}} [[` 间距」6 项）——覆盖同行 / 跨行 / 注释在前 / 单独成行 / 一高亮两注释 / 未闭合注释、**注释右侧回填空格 6 项**（紧贴链接 / 紧贴 `![[` 嵌入 / 紧跟字母 = 回填；紧跟句点 / 紧跟中文 / 块尾 = 不回填）、**默认占位符 hint 1 项**、`_render_cloze` 四种形态（含带 `==` 标记的）、`==` 与 WJ 的层次、幂等（内容首尾是 `=` 不再包）、空内容不包、先剥粗体再包标记、插件正则命中（含「内容带 `}` 预期失配」这条已知缺口）、**语义 hint 包裹 11 项**（`mark_hint()`：纯文字 / 字母 / 含空格 / 首尾标点只补对应那一侧的内层 WJ / 已包过不重复 / 含 `==` 跳过并 WARN / 首字是 `=` 不包 / 空串原样；外加 `DEFAULT_HINT == mark_hint('...')` 同构、带 `%%提问%%` 的端到端展示态 `[==提问==]`）、**`}}` 与 `[[` 间距 6 项**（`norm_link_gap()`：一空格 → 两空格 / 已两空格不动 / 三空格不动 / `![[` 不动 / 后面不是链接不动 / 端到端落成两个空格）、**清格式 21 项**（2026-09-20 新增，`strip_inline_md()`：`**` `__` `*` `_` `~~` 五类各清 1 项 + `$…$` 公式整段原样 1 项 + 行内代码与 HTML 标签原样 5 项 + 幂等 5 项 + 提问侧同一把尺子 3 项）。

⚠️ 四个必知的坑：

1. **提问里不能含 `}`** —— 第三段是 `[^}]*?`，含 `}` 会让**整个** cloze 失配，卡面直接露出 `{{c1::…}}` 字面量。脚本会剔除并打 ⚠，预览时留意。
   **⚠️ 挖空「内容」里含 `}` 同样会失配**（第二段也是 `[^}]*?`），脚本**没有**自动处理（全库实测 174 个高亮会撞上，集中在数学笔记：`$\frac{1}{2}$`、`$\boxed{A}$`、`\begin{pmatrix}…\end{pmatrix}` 这类带 LaTeX 分组的）。两种坏法：
   - `}` 在内容**中间** → 整条失配 → 卡面露出 `{{c1::…}}` 字面；
   - 内容以 `}` **结尾** → 能匹配但**吃掉末尾那个 `}`**（`\text{甲}` 被截成 `\text{甲`），答案面静默少个括号。
   **现状是"不处理、只在预览里人工盯"**（广哥定的）。可行绕法只有把 `}` 写成 HTML 实体 `&#125;`（正则层面验证通过），但 markdown-it 的 math 规则跑在 entity 规则之前，**公式内部大概率显示字面 `&#125;`**，需实测才能启用。
2. **答案里含 `::` 会被误当成提问**（`{{c1::a::b}}` → 答案 `a`、提问 `b`）—— cloze 语法的固有限制，不是脚本 bug。
3. **`_render_cloze` 的 `CLOZE_RE` 必须跟着认第三组**（现已改成 `[==提问==]` / `[==⁠...⁠==]`），否则本地幂等键与插件展示态对不上 ⇒ **每跑一次多一整批卡**。
4. **改规则 = 结构性变化**：笔记里新加了 `%%` 之后，那些块的 `Text` 变了 ⇒ 幂等键不认旧卡，复跑会**再建一批重复卡**。正解：先 `POST /cards/remove-from-note {source_uid}` 清空该笔记再重建（清完跑一次 `TR清理` 收孤儿）。
   **⚠️ 反过来，规则改「窄」也可能只伤到少数几张卡，不必清整篇**：那次加的是「注释右侧回填空格」（规则 3），只影响**注释后紧贴 `[`／字母数字**的块 —— 全库就 6 张卡，且**笔记一个字没改**。做法：只把这几张卡的 `Text` 用 `POST /cards/:id/update {question: …}` 补上空格（不动 `Extra`／`source_text`／FSRS 调度，进度不丢、不攒孤儿），再按「幂等」那节的办法只读复核（`existing_keys(uid)` 比 `card_fields_key(_render_cloze(Text), Extra)` 与 `source_text`）——**37 张全部命中、0 张对不上**才算过。
   判据一句话：**改的是「笔记怎么读」就清整篇重建；改的是「笔记怎么被转成卡面」且笔记没动，就只补受影响的卡。**

   另外两条原生命中路径仍可用于卡片面板：鼠标移到某行上（`hover` 高亮），或行右端 `⋮` / 右键 → `Open Source`（打开源笔记 + 滚动居中 + 黄底高亮 2 秒）。若面板里没反应，查该卡的 `source_text` 是否为空串、是否与笔记正文逐字一致。

   先"插件已停"（禁用插件或退出 Obsidian 均可，见铁律 2）→ 跑
   `python "...\scripts\tr_db_cleanup.py" --apply [--vacuum]`。
   脚本自带两道拦截：**先探插件 Local API 端口（默认 27182，会先读 `data.json` 的 `apiPort`）→ 探到就拒跑**；探不到还会等库文件 mtime/size 连续两次稳定，确认最后一次落盘写完才动手。默认只预演，`--apply` 才写，写前自动备份、写后复探一次（若插件又活了会强警告）。端口改过用 `--port N`。若为此停了插件，清完记得请用户重新启用。

### 幂等

幂等键 = **归一化后的 `fields_json`**（`json.loads` 后按 `separators=(",",":")` + `sort_keys` 重新序列化），且只认「**note 未删 且 它的 card 未删**」的卡。

- 为什么必须归一化：插件落库是紧凑 JSON，Python 默认带空格；不归一化就永远匹配不上 → 每次跑都重建一批。实现见 `_norm_fields()` / `card_fields_key()`。
- 为什么必须走 `/query`：插件**落盘有延迟**（实测建卡后磁盘 30 秒内可能仍是旧状态，而 `/query` 立即可见）。读磁盘 = 建完马上重跑会重复建。
- 为什么必须 join cards：只查 `notes` 会把"孤儿 note"（card 已被删）当已存在 → 整批跳过、一张都不建。
- **落盘后必须复跑一次确认"新增 0"**；`--sqlite` 路线按同一套归一化键比对。

## 4. 自检清单（每次执行后核对）

1. 预览的块数是否和肉眼数出的「高亮所在条目数」一致；有没有把明显独立的两个知识点合成一块。
2. 块内挖空数 = 该块高亮数；**同一块里应该是多个 `{{c1::}}`，不该出现 `{{c2::}}`**。⚠️ 混用 index 的后果不是「多一张卡」而是**两张卡互相泄题**（每张卡只挖自己那个 index，别的 index 以裸内容显示，详见 6 节 的 cloze 出卡规则）。
3. `flashcard_uid` 是 8 位十六进制；同一篇笔记不要出现两个 `flashcard_uid` 行。
4. API 返回的 `created` 数 + 跳过数 = 拟建卡数；失败数为 0。
5. **复跑第二次必须 `created=0`、跳过数 = 卡数**（幂等生效的唯一证据）。⚠️ 2026-09-15 实测因降级路由的字段形态踩坑，复跑又建了一整批（详见「v2.5.0 的两处破坏性变更」第 2 条）；**看到"新增 N>0"就停手**，先查键再用 `POST /cards/remove-from-note` 清空重来。
6. 卡面里保留 `[[文件.pdf#page=N|pdf]]`、`[[文件.mp4#t=N|视频]]` 是**故意的**（卡面走 MarkdownRenderer，能点开出处），不是错误。
7. **挖空内部只剩纯文字**（`**` `__` `*` `_` `~~` 全部清掉；`$…$` 公式、`` `代码` ``、HTML 标签**原样保留**）。
8. `source_text` 非空、与笔记正文**逐字一致**（含 `==`、含 `**`——它是定位坐标，不做任何清理），且与卡面的"清格式版"允许不同。
9. 关掉 Obsidian 重开后卡片还在（留存验证）。
10. `Extra` 是 `[《笔记名》·第 N 块](obsidian://adv-uri?...&line=<真行号>...)`，**行号与该块所在行一致**（拿文章的 `Read` 行号抽查 1~2 条）；`--relink` 复跑应显示「需改 0 张」。
11. 改 `Extra` 后 `Text` 里**不该**出现 `adv-uri`（链接只放 Extra，别塞进卡面正文）。
12. **收尾残留自检已做并回报**：库里孤儿 note 数、`<vault>\临时\` 本轮中间文件清单，两项都报给用户了（只报告、不擅自删，见铁律 11）；用户同意清理后走 QuickAdd 宏 `TR清理`，清完用 `/query` 复核孤儿数 = 0。
13. **清理前后各记一次活跃卡数，两者必须相等**（清理只该动 note、不该动任何卡）；顺带单独点一下库里有没有 `note_type_id = builtin-image-occlusion` 之类的**非本 skill 建的卡**，确认它们没被牵连。
15. **问题面挖空处显示的是第三段 hint**（插件 `GS()`）：⛔ **2026-10-12 起不再包 `==`** ⇒ 有 `%%提问%%` 显示插件原生黑字 `[提问]`、没有则显示裸 `[...]`（此前 2026-09-19~2026-10-11 期间是黄底 `[==提问==]` / `[==⁠...⁠==]`）。⇒ **现在「有裸 `[...]`、有黑字 `[提问]`」都是正常状态**，不再是异常信号。给笔记**新加 `%%`** 之后再跑，属结构性变化 —— 按「2.1 节」坑 4 先 `remove-from-note` 清空再重建，别指望幂等跳过。
16. **触发宏之后，判据以磁盘日志为准**：读 `<vault>/.true-recall/tr-cleanup.log`，确认输出里出现 `已软删 N 条 | saveNow 返回 true` + `复核 现存孤儿=0`；若看到 `ABORT 全库活卡=0…` 就说明被高危闸拦下（此时应该停手去查为什么全库没活卡，而不是去建哨兵强清）。**2026-09-14 实测补：ABORT 之后不要立刻判断成"假象"** —— 先用只读 SQLite 核对 `cards.deleted_at` 的分布，读三个数（活卡 / 活 note / 孤儿）+ 最近被软删卡的时间戳：若卡是被逐条软删、且删除时刻紧跟该 note 的建卡时刻（本次实测间隔 **27s~132s**，且守卫日志同期只有分组动作、没有删卡），那就是**真删**（人在复习界面把测试卡删了、note 留成空壳），此时可以放心强清；只有"三个数与最后一次 flush 时刻明显不符"才是数据未加载的假象。
17. **题面不粘连 + 间距必须两个空格**（两级，2026-09-19 升级）：① `}}` 与 `[[` **不能零空格**（粘连，2026-09-17 修，抽查 `String(Text).includes("}}[[")` 应为 false）；② 也**不能只一个空格** —— 一空格时问题面成了 `[hint] [[…|pdf]]`，Obsidian 会把 `[hint]` 吃成**链接文字**（广哥 2026-09-19 原话「把学习动机变成链接了」），必须**两个空格**才正常（`hl2tr.norm_link_gap()` 实现，全库 43 处已同步、复跑待改 0；`![[` 按指令不动，全库 0 处）。这类"卡面渲染不好看"的报障，判据都以**只读读回卡面**（DB 的 `fields_json.Text` + `GET /cards/:id` 的展示态对账）为准，别凭截图猜。

## 5. 复习端的"跳回源笔记"是怎么工作的（源码级）

**先记死一句话：插件原生能"跳过去 + 滚动 + 高亮"的入口只有"卡片面板"，复习弹窗里没有这个能力**——所以本 skill 默认把 `Extra` 写成可点行链接（「5.5 节」），复习时**点卡面最后那行就够了**，不必再走面板/右键那条路。

卡片面板（命令 `True Recall: Show flashcards for current note` / `Open flashcard panel`；v2.5.0 里是 `open-flashcard-panel`）：

- 列表**行内悬停**（`onMouseEnter`，且该卡 `sourceText` 非空才绑）→ `onHoverSource` → `requestSourceHighlight(path, sourceText, "hover", colorHint)`：只在源笔记里加高亮类，**不滚动**；移开（`onMouseLeave`）即清除。
- **点击行**（`button.tr-panel-card-main`，onClick=`onOpen`）→ 在面板里把这张卡的**详情打开**，**不是跳转**（我 2026-09-14 曾把这一步说成"点击就跳"，是错的，已更正）。
- **跳转的真正入口**：行最右端那个**竖三点 `⋮`（`icon:"more-vertical"`；平时 `opacity-0`，鼠标悬停该行才显形）**，或**在行上右键**（`onContextMenu`），菜单里的 **`Open Source`**；卡片详情页右上角同一个菜单里也有。它走 `onOpenSource = S => S.sourceText ? handleJumpToSource(S) : handleOpenSourceNote()`：
  ```
  handleJumpToSource(card):
      if (!card.sourceText || !源笔记) return
      if (当前活动文件 !== 源笔记) await workspace.getLeaf(false).openFile(源笔记)   # 先打开笔记
      requestSourceHighlight(源笔记路径, card.sourceText, "jump", colorHint)
  ```
- 该请求由一段 Codemirror `ViewPlugin` 消费：**只对编辑/源码模式生效**（阅读模式没有 EditorView），执行
  `doc.indexOf(source_text)` → 命中则 `EditorView.scrollIntoView(pos, {y:"center"})` 居中滚动 + 加 `true-recall-source-highlight` 类，**2 秒后自动清除**；`indexOf` 返回 -1（找不到）时**静默什么都不做**。
- **复习弹窗（review）里**：唯一相关的元素是**揭示答案后**、卡片下方那行浅灰小字 **`Source: 笔记名`**（组件 `pee`：仅 `isAnswerRevealed` 时渲染），点击走 `handleOpenSourceNote()` → `workspace.openLinkText(path)`，**只打开笔记、不定位、不高亮**。所以"在 review 里点了也跳不回去"是插件的既有设计，不是操作问题（用户 2026-09-14 问的就是这个）。
- 卡片右键菜单里的 `Open source note`（`note-review` 卡是 `Open note`，面板/笔记更多菜单里也叫 `Open source note`）同样只打开文件、不定位。
- 源文件解析顺序：`source_uid` → `frontmatterIndex.getFileByValue("flashcard_uid", uid)` → 拿到路径；失败再退回 `sourceNotePath`。所以**卡片的 `source_uid` 必须等于源笔记 frontmatter 里的 `flashcard_uid`**。
- 同理，AI Agent 的"定位上下文"也用 `source_text`（`resolveGradingContext`：`r.sourceText ? sliceContext(sourceText, query, 10000) : 读整篇笔记`）。

## 5.5 卡面最后那行"第 N 块" = 一键跳转链接（2026-09-14 建，解决用户"要点三次才能跳"的抱怨）

内置 Cloze 卡型的答案面是 **`{{cloze:Text}}<br>{{Extra}}`**（源码 note_type 定义），所以 **`Extra` 就显示在卡片最下方**——复习时看到的那行 `《科一选择题最后 1》·第 3 块` 就是它。

用户 2026-09-14 的诉求：「卡片面板里要搜卡、右键找 Open Source、再切窗口，太麻烦；卡面最后那行文字能不能写成链接，我直接点过去」。**能**，做法是把 `Extra` 从纯文字改成 markdown 链接：

```
[《科一选择题最后 1》·第 3 块](obsidian://adv-uri?vault=<vault-id>&filepath=%E4%B8%B4%E6%97%B6%2F...&line=42&column=1&openmode=true&view-mode=source&anchor=<该行前40字>)
```

为什么这样就能跳（本机链路）：

1. 卡面正文由 Obsidian `MarkdownRenderer` 渲染 → `[...](obsidian://…)` 变成可点的 `<a>`。
2. 本机**没装 Advanced URI**，`obsidian://adv-uri` 由 **FakeLink** 注册并接管；它在 `app.workspace.containerEl` 上以**捕获阶段**监听 click，命中 `obsidian://adv-uri` 就 `preventDefault + stopImmediatePropagation` 并直接调 `jumpToLine(filepath, line, anchor)`——**不走系统协议、不闪窗口**。
   ⚠️ **但它的滚动对「被图片/大块撑高的行」会滚过头**：`jumpToLine` 里 `const center = safeLine >= 15;`，浅行号（如第 7 行 → `safeLine=6`）走 `center=false` 的 nearest，遇到"某行被 `![[大图]]` 撑高"就表现为**视口顶部贴到该行底部**（只能看到图的下沿）。所以：**目标是普通文本行 → 照旧交给 FakeLink；目标是超高行 → 别把 href 写成 `obsidian://adv-uri`**（捕获阶段的 `stopImmediatePropagation` 会连你自己的 `onclick` 一起吃掉，症状是"点得动也跳了、但你的日志一条记录都没有"），或者改 FakeLink 的 `jumpToLine`。详见 `references/true-recall-image-occlusion.md` §九.3。
   （即便点击发生在 workspace 之外的容器里，也会经 Obsidian 自己的协议分发落到同一个 handler，仍能跳。）
3. `jumpToLine` = 打开该笔记 → `waitForEditor` → `editor.setCursor({line: n-1})` → `scrollIntoView`（行号 ≥15 时居中滚动）。编辑器 = 编辑/源码模式，**顺带满足 True Recall「只在编辑模式高亮」的前置条件**。
4. `anchor`（该行前 40 字）对应 FakeLink 的 `lineLinkSelfHeal`（本机 **= true**）：笔记改动导致行号漂移时，它按 `startsWith(anchor)` 重新找行，找得到就自动纠正。所以**链接要带 anchor**；真改了笔记内容后仍应以本 skill 重跑 `--relink` 刷新行号。

要点：

- **只改 `Extra`**：`Text`、`source_text`、FSRS 调度（`state/due/...`）都不动 → 既不重置复习进度，也不新建 note（**不会再攒孤儿 note**）。
- 走 `POST /cards/:id/update {answer: "<新 Extra>"}`（服务端 cloze 分支写 `fields.Extra`），**需要 Obsidian 在跑 + Local API 开着**。
- **幂等**：靠旧 `Extra` 里的 `第 (\d+) 块` 反查块号，重算后再比较；重跑显示「需改 0 张 / 已是最新 N 张」。
- 老卡片存量刷新：`hl2tr.py "<文件>" --relink`（预览）/ `--relink --apply`（写回）。**不用重建卡**，因此不必碰 `remove-from-note`。
- `vault=` 参数从 `%APPDATA%\obsidian\obsidian.json` 动态读取（本机 `<vault-id>`）；读不到就省略——FakeLink 只认 `filepath/line/anchor`，功能不受影响。
- 链接较长（带 anchor 约 500 字符），但**渲染后只显示"《笔记名》·第 N 块"**，不影响阅读；`--no-anchor` 可显著缩短。

## 6. 已知边界

- ⚠️ **直写 SQLite 会被插件清掉**（v2.4.2 实测，v2.5.0 机制未变）。现象与根因见铁律 6 与「3. 执行流程」第 7 步。**优先走 Local API**。
- **落盘延迟**：插件写库有延迟（建卡后立刻读磁盘仍是旧值，数秒后才变；`/query` 立刻可见）。查状态一律走 `/query`（v2.5.0 若 `/query` 被关，走 `GET /notes/cards`，同样读插件内存），或等几秒再看磁盘。
- **⚠️ 直写 SQLite 做「软删」必须同时抬 `updated_at`（2026-10-01 实测定案，2026-10-02 审查补入）**：只 `UPDATE ... SET deleted_at=<now_ms>` 会被应用同步的 upsert **回滚**——守卫 `excluded.updated_at > notes.updated_at` 成立时整行覆盖、`deleted_at` 被抹回 `NULL`，删了等于没删，且**不报错**。**正解 = 同一句 `UPDATE` 里把 `updated_at` 抬到远未来**（现 + 10 年毫秒），守卫从此永不成立，删除即持久。复核 = 跨进程 + 延迟 8 秒再读该行，Obsidian 运行时也一并复核。**误删可逆**：把 `deleted_at` / `updated_at` 清回 `NULL` 即还原。注意铁律 6 被证伪的是**新增卡**方向，软删方向不受它限制。
- **⚠️「完整删卡」是两步，插件的任何删除入口都只做第一步**：
  ① **删卡** —— 五条入口全部只给 `cards.deleted_at` 打时间戳（软删、可还原）：复习界面 `Shift+1` / 右键 Delete card（**连带**，见铁律 9）；卡片面板 `⋯ → Delete all cards`（该文件名下全部卡，带 Undo）；卡片面板 `⋯ → Delete note & cards`（同上 **+ 把 `.md` 丢进回收站**，*This cannot be undone*，只在笔记也不要时才用）；手动删 `.md` → `handleFileDeletion` 自动软删该文全部卡；API `POST /cards/remove-from-note {source_uid}`（最干净、可撤销，脚本首选）。
  ② **清空壳** —— **插件永远不会删 `notes` 行**（全库只有 `disableNoteReview` 一处调 `notes.delete`）⇒ 第一步跑完**必然**留空壳 note，再跑 QuickAdd 宏 `TR清理` 才算真的干净。两步都只软删、都可逆。
- **孤儿 note**：API 建的卡是「一条 note + 一张 card」。删卡只软删 card、**note 留下** ⇒ 反复重来会累积。它们没有活跃卡，复习/浏览器都看不到，**不影响使用**。清理两条路（用法见第 9 步）：**路线 A** = QuickAdd 宏 `TR清理`（`<vault>\Scripts\truerecall清理.js`，不停插件、不关 ob、AI 可用 `obsidian://quickadd` 触发）；**路线 B** = `scripts/tr_db_cleanup.py`（脱离 Obsidian，前置「插件已停」——设置里禁用即可、不必退 ob；探到 API 端口就拒跑；默认预演、`--apply` 才写、写前自动备份、`--vacuum` 回收）。两条都只填 `notes.deleted_at`（不 DELETE、可还原），删前做误伤检查（挂活跃 card 的 note 一律排除）。
  **⚠️ 插件的「Check integrity」修不了这类孤儿**：它认的 `orphanedNotes` 是「`note_type_id` 指向不存在的 note_type」（悬空外键），**不是**没有卡的空壳；且 `GET /integrity` 只跑 `check()` 不跑 `repair()`。
  **⚠️「AI 无法自动启停插件」只对了一半**：Local API 71 条路由里确实没有插件管理接口、禁用后 `localApi.stop()` 还会自锁，但 **QuickAdd 的 UserScript 跑在 Obsidian 内部**，`app.plugins.disablePluginAndSave/enablePluginAndSave` 直接可用（本机 `Scripts/fakelink开关.js` 就是这么写的）。不过清孤儿不必这么绕——路线 A 连插件都不用停。
  **删掉源笔记同理**：插件把名下卡片全部软删，但 note 空壳**全部留成活的孤儿**，重启 / 重载也不自动清 ⇒ 仍要跑一次清理。
- **少攒孤儿 = 少删重建**：脚本已按归一化 `fields_json` 幂等跳过，内容没变就不动手；只改 `Extra` 时用 `--relink`（走 `POST /cards/:id/update`，原地改、零新增 note）。只有「块数增减 / 挖空结构变了」这类结构性变化才需清空重建。
- **持久化架构**（解释"为什么要插件停"）：插件不用原生 SQLite、无文件句柄无锁——sqlite3 编译成 WASM 塞进 `main.js`，建的是 `:memory:` 内存库（`sqlite3_deserialize` 导入磁盘字节），写盘走 Obsidian `vault.adapter.writeBinary/rename`。所以"文件被占用"不是问题；真问题是 **`onunload()` 的 `coreApp.shutdown() → cardStore.saveNow()` 会把内存整库覆盖到磁盘**，失败只打一行 `Final data flush failed`。落盘是**原子替换**：写 `.db.tmp` → 校验字节 → 旧库改名 `.db.bak` → tmp 改名 `.db` ⇒ **目录里的 `.db.bak` 是插件自己留的上一版，别当垃圾删**。
  推论：① 插件活着（或刚禁用、saveNow 未完成）时改库会被内存版盖回去；② 插件另有 `backups.nosync/` 周期备份 + 启动时的 `integrity.checkAndRepairOnce()`（靠 `meta.integrity_checked` 只跑一次）。
- 只认 `==高亮==`。Spaced Repetition 插件已被卸载，那套 `::` / `?` / `#flashcards` 语法不必再考虑。
- **⚠️⚠️ 在插件编辑器里编辑 cloze 卡，会把字段写成 `Front`/`Back`，卡当场坏掉（2026-09-19 实测）**：note 的 `note_type_id` 仍是 `builtin-cloze`，但 `fields_json` 变成 `{"Front": <渲染后的整面 = Text 渲染值 + `<br>` + Extra>, "Back": <渲染后的问题面>}` ⇒ cloze 模板 `{{cloze:Text}}<br>{{Extra}}` 两个字段都取不到，卡面渲染异常。**根因**：编辑 UI 是用 `GET /cards/:id` 那套**运行时渲染值**（question / answer）填两个框的，保存时按 `Front`/`Back` 原样写回，**没有按 note_type 映射回 `Text`/`Extra`**（写进去的 `{{c1::}}` 早已被展开成 `**==…==**`，cloze 语法一并丢失）。
  - **判据（巡检 SQL）**：`note_type_id='builtin-cloze'` 且 `fields_json` 的键不含 `Text`/`Extra`；反向也扫 `builtin-basic` 缺 `Front`/`Back`。
  - **修法**：`POST /cards/:id/update {question: <带 `{{c1::}}` 的 Text>, answer: <Extra>}`（**只改 fields，不动 FSRS 调度**）。`Text` 三个来源按优先级：① `.true-recall/backups.nosync/**.db.gz` 里改前那份（解压后按 note id 读），② 源笔记 `source_text` 重跑 `plan_cloze()`，③ 手工把 Front 里 `**==X==**` 逆回 `{{c1::X::hint}}`；`Extra` = Front **最后一个 `<br>` 之后**整段（模板里 Extra 就在那儿）。改完复核：库里异常数归 0 + `GET /cards/:id` 的 question 是 `[hint]` 形态、answer 是 `**挖空**<br>Extra`。
  - **预防**：**要改 cloze 卡的内容，就改源笔记再重跑本 skill，别在插件编辑器里改**（basic 卡不受影响——它本来就是 `Front`/`Back`）。
- **⚠️ 卡面里的 `{{c1:xxx}}`（单冒号）是坏数据**：插件正则要 `{{cN::`，单冒号认不出 ⇒ 卡面**露字面量**。脚本不会产出这种写法（它只出 `{{c1::}}`），来源是手工改卡面或别的路径写入。**巡检卡面时顺手扫 `\{\{c\d+:[^:]`**。
- **⚠️ cloze 闭合 `}}` 紧贴 `(` 会渲染异常（广哥 2026-09-26 实测）**：`{{c1::…}}(文字)` 这种 `}}` 与 `(` 之间无空格的写法，渲染会错断残段（实例：露「发展阶段⁠==}} (寻求」这类半截字面量）。**手工写卡面 / 改库拼 Text / 脚本拼接时，`}}` 与后续 `(` 之间必须留一个空格**。与上一条「单冒号坏数据」同属渲染层语法坑。
- **卡面 Text 里带两类脚本有意加的标记**：`U+2060`（WJ，不可见、复制卡面文字时会一起被复制走）与 `==…==`（挖空内容外那层）。两者**都不进 `source_text`** ⇒ 跳回原文与幂等比较都不受影响。
- **同块混用 index 会互相泄题**：出卡时只有本卡的挖空变 `[...]`，别的 index 以裸内容显示（插件 `GS()`／`rI()` 行为），裸内容带 `==` ⇒ 问题面冒黄底、且两张卡互泄答案。**本 skill 的产出不会踩到**（一块永远是同一个 `{{c1::}}` 多份）。**⚠️ 两条别走回头路**：① 别再「把问题面的 `.cm-highlight` 抹成透明」——cloze 卡答案就渲染在问题面容器，那会掐掉唯一钩子；② 别再用 `.cm-highlight:not(.cm-strong)` 压平裸内容——单 index 下无目标、却会误伤「挖空被用户 `**` 包住」的黄底。**正解永远是「一块一个 index」。**
- **cloze 出卡规则：一个 index 一张卡，卡与卡【不互相遮挡】**。`Qfe()` 返回 `US(Text)`（全文 `{{cN::}}` 去重排序）⇒ 几个 index 就几张卡（`c1`+`c2` = 2 张，`template_ord` 1、2），**但每张卡只把本 index 变 `[...]`，其它 index 剥掉花括号原样露出** ⇒ 混用必然泄题。所以「一块只用 `{{c1::}}`」不是风格问题，是**避泄题的必要条件**。根治 = **把 `c2` 改成 `c1`**（读 `notes.fields_json.Text` → 全部 `{{cN::}}` 统一成 `{{c1::}}` → `POST /cards/:id/update {question}` 写回**一张**卡；**另一张不用删**——插件发现只剩一个 index 会自动软删 ord 2，再发 `DELETE` 会 404）。判据：合并后 `{{c1::}}` 数 = 原挖空总数、`{{c2::}}` 为 0、内容内残留 `**` 为 0。
- **⚠️ 卡面上可能有「野生 `{{cN::}}」——源笔记里根本不存在**。成因：`editCount` 有增长 ⇒ 有人在插件里手编过卡片，`note.Text` 是唯一真源、与源笔记脱钩。**判据**：`note.source_text` 没有 `{{c` 而 `note.Text` 有 ⇒ 野生。后果：**重建这篇时这些挖空会消失、那张卡也会没**。规范化 = ① 剥掉散落的 `**`；② 内容两端包 `==…==`；③ 两端插 WJ；**index 保持不变**（只让渲染干净，**泄题照旧**）。要永久保住须先在源笔记对应行补 `==…==` 再重建——合并 index 不改变这一点。
- **批量补内层 WJ**（迁移用，一次跑完 35 篇 / 36 处）：脚本 `tmp\tr_harden_edge_wj_20260917.py`（已清、需要时照此重写；dry-run 默认、`--apply` 落库；只往 `==` 内侧插 WJ，不动 c 编号 / 内容 / `Extra`，幂等）。复核标准：**会露字面 `==` 的挖空必须为 0**。
  ⚠️ **`/cards/:id/update` 只传 `question` 不会清空 `Extra`** ⇒ 批量迁移不必回传 `answer`。⚠️ 落库后**别立刻用库文件复核**（写盘有延迟），要么等、要么读插件自己的连接。
- **`/cards/:id/update` 的字段落点**：`cards` 表**没有** question/answer 列 ⇒ 传进去的 `question` 实写进 **`notes.fields_json.Text`**、`answer` 写进 **`notes.fields_json.Extra`**；而 `GET /cards/:id` 返回的 question/answer 是**运行时渲染值**（挖空已变 `[...]`），**不是存值**。⇒ 别把 GET 回来的 `question` 原样 POST 回去（会把模板写坏）。

## 7. 统计面板的数字为什么删卡后还在（一句话 + 指针）

`Statistics` 上的 Studied today / Minutes / Correct / Current streak，**无筛选时读的是预聚合表 `daily_stats`**；而删卡（`bulkSoftDelete`）只软删 `cards` + 这些卡的 `review_log`，**从不更新 `daily_stats`** ⇒ 卡删光了、复习记录也软删了，数字照样留着。插件**没有**「清空统计」入口（命令面板 37 个命令里没有；`POST /query` 只放行 SELECT，从外部也清不掉）。

**正解** = 调插件自己的重建方法 `plugin.cardStore.stats.rebuildDailyStatsFromReviewLog(dayStartHour)`（先清空 `daily_stats` + `daily_reviewed_cards`，再从**未软删的 `review_log`** 重算 —— 权威源只有 `review_log`；插件在设备/云同步拉到数据后也是这么修的）。**本机实现（2026-09-14.3 起已并入 `TR清理` 宏，不再有独立宏/脚本）**：`MODE="auto"`（默认）= 清完孤儿顺手重建，`"stats"` = 只重建、`"cleanup"` = 不碰统计、`"report"` = 只报告；**是否重建由判据决定** —— `daily_stats` 的复习总次数与未软删 `review_log` 条数对不上才重建（纯函数 `statsDiagnosis`；相等就跳过，不做无谓写库）。重建前写 undo 快照，建 `.true-recall/stats-restore.flag` 可还原。

> **为什么合并**（2026-09-14 广哥问「这个脚本不能写在 TR清理 里面吗」）：两份脚本近八成是同一套东西（就绪闸 / 避让闸 / `pickStore` / 日志 Notice 框架 / undo 清单读写），当时分开写只是因为两个问题先后提出；而且「删完卡 → 清掉空壳 note → 统计数字还留着」本来就是**同一次收尾**——分开时跑 `TR清理` 看到「无孤儿」就早退了，还得再想起第二个宏。合并后 `TR清理` **「无孤儿」不再早退**，继续走统计环节（这正是原 `TR统计重建` 的活）。退役物：脚本 `truerecall统计重建.js`、QuickAdd 宏 `TR统计重建`（两者 2026-09-14.3 删除，备份在 `.workbuddy\tmp\tr-merge-backup-20260914\`），旧测试台 `scripts/test_tr_stats_rebuild.js` 的用例并入 `scripts/test_tr_cleanup.js`（187 项）。

⚠️ 三个别踩的坑：① 用 preset/archived 筛选能让数字当场显示 0，但那只是切到"从 `review_log` 现算"的视角（该路径 SQL 写死 `deleted_at IS NULL`），**取消筛选就回来**，而且以后每次复习是 `旧值 + 新值` 累加，旧值会一直叠在上面 —— 必须重建；② 重建后**不用重载 Obsidian**，但**必须让面板重新取一次数**：主 `Statistics` 视图持有一个**与视图同寿命**的统计实例（`Ce(…, [plugin])`），自带 `dailyStatsCache`，取数只在「卡片集合／筛选／时间范围／面板可见性」变化时重跑，**不会**因 `daily_stats` 被外部改写而刷新 ⇒ 脚本重建完，**已经开着的面板会继续显示旧数字**（2026-09-14 实测：日志已写 `复核 daily_stats=0 天`、只读查库确认 0 行，面板仍显示 41 / 79 / 80% / 2d，**点一下 `Archived` 立刻变 0**）；③ 因此**判据看日志那一行或直接查库，别信面板** —— 关掉面板重开、点筛选、切时间范围任一条即可见新值，脚本够不着视图里的缓存，也不要去清（`2026-09-14.4` 起重建成功时 Notice 里已带这句提示）。
