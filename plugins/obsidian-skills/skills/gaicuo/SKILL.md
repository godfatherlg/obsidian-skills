# 改错（手写简答答案批改）

用户的教资/考研简答题手写答案批改。输入两样：①题目的位置线索（两种形态，见下）；②一张手写答案照片。

**题目位置线索的两种形态（2026-10-10 广哥定）**：
- **形态 A**：一个 obsidian://adv-uri 链接（标题链接或行链接，指向题目位置，答案在该标题内或该行下面）→ 按第 2 节读 vault md。
- **形态 B**：一段**复制的纯文本**（没有链接、不是图片路径）→ 这段文本就是 **True Recall 里某张卡的题目（卡正面 Front/Text）**，答案在卡背面 → 按第 2 节「2A. 从 True Recall 查卡」查库取答案面。

**最终返回顺序（这是本 skill 的核心契约，改动过口径）**：
1. **先出对照图**（`show_widget` 内联 SVG）——这是回复的**开头**，全图分块排布（见第 6.0 节）。
2. 再给三块文字：评分（10 分制，主分＋区间说明）／错误（漏辨识词・漏措施点・口径差异）／遗漏关键点＋记法＋关键词（每条三件套，关键词加粗）。

转写、参考答案逐条对照是**内部核对步骤，不全文返回**；仅当手写图有认不准的字时才在回复里列出请用户纠正。

本 skill 面向 flash/低资费模型：所有本机事实、命令、模板都写死，不要现场摸索；正文走祈使句，只读不写。
对照图的**颜色与坐标规格**单独立文在 `references/chart-color-scheme.md`（唯一真源），画图前必读、照抄取色。

## 0. 铁律（先读）
1. 只读不写：不写任何 vault 文件、不改笔记、不建 True Recall 卡、不生成交付文件、不 present_files。纯聊天批改。
2. 标题带 ⭐/⏳ 会连带触发 heading-to-true-recall 的建卡诉求——本 skill 只把带背稿正文当参考答案读，忽略建卡诉求，不建卡。
3. 引用库内内容一律按 obsidian-jump-line 三态链接写（**Markdown 链接形态 `[行号](obsidian://…)`，外层不套任何包裹符号**）。本 skill 输入含 obsidian:// 链接，会连带触发 obsidian-jump-line 提示——照它的链接格式做。
4. 回复格式遵守第 6 节的用户聊天硬约束。
5. 最终返回＝**先对照图、再三块文字**。转写与逐条对照是过程、不返回；认不准的字才列出来请用户纠正。对照图是回复的开头，不是可选装饰（2026-10-09 广哥定）。
6. **判漏必先过「简写豁免闸」，禁止拿全称逐字扣简写**（2026-10-10 广哥当场纠错，本次实测翻车）：比对前先把参考答案每条还原成**核心关键词**，只判关键词在不在、对不对；**用户省略的重复词／限定词／展开句一律不扣分**。两个已知雷区：
   - 省略**重复出现的词**：九智全名都含「智力」二字，用户写「言语、音乐、运动」＝写全了，**不得**判「漏『智力』」；同理「数学逻辑」是「逻辑-数学智力」的简写、**不得**判「漏『逻辑』」。
   - 词序／近义词差异属**简写**不属错：稿里两种写法并存时（如「视觉-空间智力」与「视觉空间智力」）用户写任一即可，**不得**按另一版判错。
7. **手写图上的线条／箭头默认按「展开箭头」读，禁当答题逻辑关系判**（2026-10-10 广哥定）：用户会用一个框写口诀字、再用线连到它展开的智力名（如「存」→存在、「自」→自知、「人」→人际），这是**背诵示意**、不是「多因一果」。**读图时先假定「一线一展开」，判不准就问一句，禁止据此判「对应错乱」**。线条若只表串记顺序，按 `references/chart-color-scheme.md` 第 4 节第 5 条用灰 `#888780`、不参与严重度着色。
8. **用户当场指出判错时**：立刻按本条重走一遍豁免闸，承认判错并说明根因（是「拿全称比简写」还是「误读示意图」），再给修正分；**不要**先辩解、不要只改分数不改判据表述。
9. **参考答案里的补充说明不算答题要求，没写不扣分**（2026-10-10 广哥定）：带背稿/卡片答案中凡属**背景介绍、定义引申、拓展举例、出处说明、考频提示、真题例子、记忆钩子（口诀/人物串记）**等非采分内容的句子，一律视作**供了解**，不进入比对、不判漏、不标红。**识别按语义判断，不依赖任何标记**（答案里没有专门记号，需 AI 自己读语义区分「答题要点」与「补充了解」）。判不准算不算采分点时，按「不扣分」处理（宁可宽松）；只有确实是本题答题要点（需背、需答）的句子才参与判漏。此条与第 6 条简写豁免闸**并列，先过此条再过简写闸**。
10. **判漏前先验转写：转写与参考答案明显对不上的整句／整行，先按「OCR 漏译」处理、用 Read 补核，再判漏**（2026-10-19 广哥当场纠错，实测翻车）：GLM 会「看了图仍漏译／改写整行」，脚本的复述自检只防「不看图照抄参考答案」、防不住这种「看了图漏一行」。**转写漏译 ≠ 用户没写**——没补核就判漏、把用户写到的核心词判成「全漏」，等于拿转写当事实（实例：第三行「即,非人为的本质性的知识的理解」被 GLM 改写成「即学生在理解知识的实际意义的基础上，掌握知识的本质和规律」，「非人为的」被吞，被误判成没写）。补核用 Read 看原图（只在此时启用，见第 3 节第 4 步）；补核后仍缺的关键词才算漏。**⚠️ 本条在铁律 6（简写豁免）与铁律 9（剔补充说明）之前执行**——先确认转写没漏译，再谈豁免与补不补充；顺序反了会把「转写漏译」当成「用户没写」豁免掉。

## 1. 本机事实（写死，别摸）
- vault id = <vault-id>，根 <vault>。
- **链接唯一真源 = `obsidian-jump-line`**：本 skill 不自己造链接模板，一律照它的三态写（精确到行→显示行号数字；指标题→`标题`；指整篇→`line=1`＋`文章`）。URI 模板：`obsidian://adv-uri?vault=<vault-id>&filepath=<编码相对路径>&line=N&column=1&openmode=true&view-mode=source`。
- **每个链接必须当场用 Python `urllib.parse.quote(rel, safe="")` 重新生成**（`/`→`%2F`、中文百分号编码）；**禁止照抄上一轮回复的旧串、禁止手写编码、禁止凭记忆改字**（2026-10-05 漏字事故：手写串比真路径短 1 字 ⇒ FakeLink 静默不跳、零报错）。禁 anchor、禁 offset、禁 page=。
- **⚠️ 路径必须是「vault 根起」完整相对路径（2026-10-21 第二次链接事故根因）**：本工作区是 `<vault>\2026上数学教资`，vault 根是 `<vault>`，所以 `冲刺班/科二/xx.md` 这种「工作区起」的写法**漏了 `2026上数学教资/` 这一层** ⇒ 百分号编码完全正确、`--check` 也全绿灯，但 FakeLink 找不到文件、**链接点了没反应且零报错**。`gaicuo_link.py` 现已内置存在性校验：漏前缀会自动补全并打印 `<-- 漏了工作区前缀，已自动补全`，找不到文件直接报 ERROR 并退出码 1；**看到这两种提示必须改路径重生成，不许当噪声略过**。
- 形态：**必须写成 `[行号](obsidian://…)` 的 Markdown 链接**；本小节的"不套包裹"只针对反引号 / `$...$` / 代码块 / 整条列表项栅栏（任一种都会让链接**失去可点性**）。**只贴裸 URI = 不合格**——客户端不渲染、点了没反应，编码再对也白搭（2026-10-21 广哥当场退回"你写的链接我不能点"）。
- **收尾必做双向自检**（见第 7 节第 9 条）：`len(生成串)` 与 `len(quote(真路径))` 必须相等，且 `unquote` 回来逐字 diff 为零；不等就是漏字，重生成，不许交卷。
- 「相关 vault 笔记」条目格式：`N. 《文件名》第N行 — 一句话简述`，行号写成可点链接，**不写「（路径：…）」**、不写裸路径。
- 对象边界：只链 **vault 内可打开笔记**；`.workbuddy/` 等点开头目录下的工作区文件（两层 MEMORY、每日日志）**不加链接**，如实写路径。
- gaicuo_ocr.py 用独立 paddle venv 跑：`~\.workbuddy\binaries\python\envs\paddle\Scripts\python.exe`（含 PaddleOCR 3.7.0 GPU 版 + Pillow）；gaicuo_tr_find.py 用 default venv 跑（`~\.workbuddy\binaries\python\envs\default\Scripts\python.exe`，含 pillow）。
- **手写图转写主流程（三步，2026-10-19 重写）**：
  **第一步·跑脚本**：`scripts/gaicuo_ocr.py <图> --ref <答案md> --refline 起行,末行`。脚本内两条 OCR 腿自动调度：① **GLM-4V-Flash**（免费多模态 OCR，key 在 `~/.workbuddy/.env` 的 `ZHIPUAI_API_KEY`，脚本启动自动读入、回退 `ZHIPU_API_KEY`；把答案原文当词表，识别时就地按答案靠拢）；② 兜底 **PaddleOCR**（GPU 3.7.0、PP-OCRv6 中文模型已缓存、本地不联网，只出纯转写）。GLM 慢/失败（超时、限流、网络错、无 key）→ 脚本自动回退 Paddle。
  **第二步·看 stderr 标记**：见下一段「复述防护」。看到「疑似未看图复述」「对拍一致/对拍不符」即该轮走了对拍分支，**转写以 stdout 为准**。
  **第三步·核漏译（必做，2026-10-19 新增）**：GLM 的已知失效模式不是「完全不看」，而是**看了图仍漏译／改写整行**（实例：第三行「即,非人为的本质性的知识的理解」被改写成「即学生在理解知识的实际意义的基础上，掌握知识的本质和规律」，「非人为的」被吞）。所以转写出来后必须与参考答案**逐行对表**：与答案明显对不上的句子/整行，**默认先当「OCR 漏译／误译」处理、不当用户没写**；对该行用 **Read 看原图逐字补核**；补核仍认不出的字，才在回复里请用户纠正。**只有补核后仍缺失的关键词才交付判漏**（第 0 节第 10 条）。
  **Read 的定位**：Read 是文件读取工具、**不是 skill**——把图片递给当前对话模型、靠模型自带的多模态看内容。它**只承担第三步的补核**，不是每次必做（没有漏译嫌疑就不调用）；模型没有多模态能力时跳过此步，转写以 GLM/Paddle 为准，**主流程不受影响**（两条 OCR 腿都不依赖对话模型看不看得见图）。**⚠️ 但这不代表可以省掉补核**：对话模型无多模态能力时，**先按用户级 MEMORY 走 `/model` 切一个有多模态能力的模型再补核**；切不到（或不想切）才跳过补核，**并在回复里注明该轮未补核**（第 0 节第 10 条：未补核的转写不得作为判漏依据）。
- **GLM 静默复述防护（2026-10-18 实装）**：GLM 偶发「不看图、直接复述参考答案」（只查非空即成功的旧逻辑完全漏判，2026-10-18 日志有实例）。现脚本带自检：输出与参考答案高度相似（相似度 ≥0.85 或最长公共子串 ≥15 字）时自动转 PaddleOCR **对拍**——图片内容与输出不符才判复述、采用 PaddleOCR 转写；两路一致说明作者工整默写、GLM 输出可信（防误杀）。stderr 会打「疑似未看图复述」「对拍一致/对拍不符」标记，**看到这类标记即说明该轮走了对拍分支，转写结果以 stdout 为准**；如对拍后仍怀疑复述，可临时加 `--no-glm` 强制 PaddleOCR。

## 2. 定位参考答案（第一步）
0. 先判别题目位置线索的形态：
   - obsidian:// 链接 → 走下面 1-4 步读 vault md。
   - 复制的纯文本（无链接）→ 直接跳本节末「2A. 从 True Recall 查卡」，查到的答案面当参考答案，跳过 1-4。
1. 解析链接：取 filepath 用 `urllib.parse.unquote` 还原成 vault 相对路径，取 line。
2. Read 该 md（绝对路径 = `<vault>\` + 相对路径）。
3. 判定答案范围：
   - line 是标题行（`^#{1,6}\s+`）→ 参考答案 = 该标题行到下一个「层级 ≤ 它」的标题之间的所有行（标题下的正文）。
   - line 不是标题（行链接）→ 先向上找最近的标题，参考答案 = 该标题到下一个同/高层级标题之间的所有行（该行所在的那一整道简答题）。
4. 带背稿结构：每个 `##` 标题 = 一道简答题，标题下多行 = 答案（分条列出特征/措施/口诀）。标题里的 𒋙/⭐/⏳/(N题) 是标记，读答案时忽略，只看正文。

## 2A. 从 True Recall 查卡（题目是复制的纯文本时，2026-10-10 广哥定）
1. 跑 `python scripts/gaicuo_tr_find.py "<复制的题目文本>"`。脚本连插件 Local API 的 `/query`（127.0.0.1:27182，本机 `apiEnableSqlQuery=true`；token 自动读 `highlight-to-true-recall/.local-api-token`，本机已配）。
2. 脚本在全库活卡里按题目做归一化匹配（去空白 + 去 `𒋙⭐⏳==**` 标记），先精确相等、再子串包含；命中多张全部打印、按强度降序。
3. 取答案面当参考答案：**basic 卡取 `Back`、cloze 卡取 `Extra`**（脚本打印的「答案(Back/Extra)」那行）。命中多张 → 按题目内容挑最贴的一张（脚本已按强度排序，默认取 `[1]`）。零命中 → 报告「库里没有这道题」，请用户确认文本是照卡面正面原样复制的、或改贴 obsidian:// 链接。
4. 读答案面时**忽略末尾那行 `[[笔记#标题|标题]]`**（那是建卡时加的跳回原文链接，不是答案内容）；正文里的 `[[X.pdf#page=N|pdf]]`、`[[X.mp4#t=N|视频]]` 同理是出处，不算采分点。
5. OCR 要喂参考答案当词表时：先 `python scripts/gaicuo_tr_find.py "<题目文本>" --dump <临时md>`（或 `--answer-only` 直接拿纯答案文本），再照第 3 节跑 OCR 时 `--ref <该临时md>`（Back 就是本题全文，不必再加 `--refline`）。

## 3. OCR 转写（内部步骤，不返回）
1. **跑脚本**（第 2 节定位并读完参考答案之后）：
   `~/.workbuddy/binaries/python/envs/paddle/Scripts/python.exe scripts/gaicuo_ocr.py <图> --ref <答案md路径> --refline 起行,末行`
   `--ref` 必带（把答案当词表）；`--refline` 只喂该题几行防超上下文。
2. **两条腿的调度（脚本自己做，不要手动指定）**：
   - **GLM 可用 → 走 GLM**：把答案当参考，**尽可能向答案靠拢，看不清的词也以此为准**（脚本 prompt 已写死：看不清的字按答案对应词写、不标 X(?)；只补个别认不清的字、不凭空补句子）。
   - **GLM 慢/失败 → 回退 PaddleOCR**：脚本自动回退本机 Paddle（GPU、本地不联网），只出纯转写；**语义纠错由当前对话模型在核对时做**——喂参考答案当词表，先对着答案猜这个字像什么、往答案靠拢，猜不到再按语言先验猜，补漏字、改错字（手写＝照答案背写）。兜底场景不调 GLM。
   - **复述自检（2026-10-18）**：输出与 ref 高度相似（相似度 ≥0.85 或最长公共子串 ≥15 字）→ 脚本自动转 Paddle **对拍**：对拍不符采用 Paddle 转写、一致则采用 GLM 转写（防误杀工整默写）。stderr 有标记，**转写以 stdout 为准**；仍怀疑复述才临时加 `--no-glm`。
   - **禁止**裁块放大重转（`--strip`/`--zoom`）、禁止逐块猜字；一步到位，不行就换 PaddleOCR，不层层放大。
3. **方向歪才加参数**：横拍/竖排/倒置 → 加 `--dir cw`（或 `--dir ccw`）旋转一版再转写，只转一版；其余情况不加参数。
4. **漏译补核闸（必做，2026-10-19 新增）**：
   - 转写与参考答案**逐行**对表；与答案明显对不上的句子／整行 → **先假设「OCR 漏译／误译」，不是用户没写**。
   - 对该行用 **Read 看原图逐字补核**（Read 只在此时启用：它是文件读取工具、不是 skill，把图递给当前对话模型）；**模型没有多模态能力时先按用户级 MEMORY 走 `/model` 切一个有多模态的模型**，切不到才跳过此步、转写以 GLM/Paddle 为准，**并在回复里注明该轮未补核**。
   - 补核仍认不出的字，才在回复里列出请用户纠正。
   - **过了这一步才能进第 4 节判漏**；未补核的转写不得作为判漏依据。
5. 转写只用于核对错误，不返回。

## 4. 评分与找错误（最终返回第①②块）
1. 对照参考答案逐条核对，先肯定写对的部分（结构完整、配对零张冠李戴、措辞准），再列错误。
2. 评分：10 分制。口径＝简答按要点采分：先看结构是否齐（总起/定义/总纲、主体各分点、收尾辨析），再看每分点拿到几成。给一个主分 + 区间说明（说明「总起/收尾是否单列采分」如何影响区间）。手写多用**简写**（只写主要关键词、省略不重要/重复内容），核心关键词写到了即该点算对，省略的展开句不扣分（2026-10-09 广哥定）。
3. 错误分三类（判漏前先过**简写豁免**：核心关键词写到了该点就算对，只有关键词本身没写/写错才算漏——2026-10-09 广哥定）：
   - **判漏顺序（硬流程，2026-10-10 加强；2026-10-20 补第 -1 步）**：**-1 转写与答案明显对不上的行已用 Read 补核（未补核不得进入本流程**，见第 0 节第 10 条）→ ⓪ 先从参考答案里**剔除「仅供了解」的补充内容**（背景介绍／定义引申／拓展举例／出处说明／考频提示／真题例子／记忆钩子等，见第 0 节第 9 条）——这些不是答题要点，用户没写**不扣分、不进比对**；判不准是否采分点时按不扣分处理。① 把**剩下的**答题要点**逐条压成核心关键词**（剥掉重复词、限定词、展开句）；② 去手写转写里找这批关键词；③ **找齐了 → 判对，一个字都不许标红**；④ 只有关键词本身缺／词本身写错才判漏／错。跳过第⓪步（把补充说明当要点扣分）或第①步（直接全文比对）的，等于违规。
   - 漏辨识词（参考答案里某分点的关键词，用户没写）
   - 漏措施点（措施类题目里，参考答案的措施条，用户少写/写一半）
   - 口径差异（用户自己加的近义词不算错，但建议贴回稿里用词）
   - **不算错的四类（写了就别标红／标橙）**：省掉重复词（九智的「智力」）、省掉限定词（「可能的」「共9种」）、词序调换（「空间视觉」＝「视觉空间」）、连笔示意图上的口诀/展开线条。
4. 特征↔措施配对核对：措施应从特征推出（缺啥补啥、怕啥避啥），判断是否张冠李戴。

## 5. 遗漏关键点＋记法＋关键词（最终返回第③块）
用户点名要的重点，按重要性降序，每条给三件套：
1. 关键点：补上参考答案里他漏的原文（不缩减）；只列真缺的——他简写已覆盖（核心关键词写到）的点不算遗漏、不列。
2. 记法：记忆钩子。按优先级选套路：
   - 特征推措施：缺啥补啥、怕啥避啥（如胆汁质怕硬→避激怒、多血质怕忘→盯验收、黏液质怕快→给时间、抑郁质怕众→私下说）
   - 人物串记：用典型人物一人串一类（孙悟空/猪八戒/沙僧/林黛玉等）
   - 对照法：相邻概念两两对照（胆汁质火=自制力差 vs 黏液质水=自制力强）
   - 一句话钩子/口诀/谐音
3. 关键词：短、可背、用「·」分隔，**加粗**，让用户照着背。
4. 最后给一条「统一逻辑线」把全部遗漏串起来（如「缺啥补啥，怕啥避啥」），考场先推、推不出再背关键词。
5. 完整范例见 `references/example-q73.md`（73 题气质的类型特征及针对性教学）。

## 6. 输出格式（聊天回复硬约束）

### 6.0 对照图（回复开头，必出）
- **回复第一条就是画图**：加载 `widget_guidelines`（`diagram`）后调 `show_widget`，把「正确答案／遗漏／写错」用图直接摆出来，用户一眼看清。图的内容同第 6.2 节的文字要点。
- **图是聊天内联 SVG，不是落盘文件**——不写 vault、不 present_files，仍守只读铁律。
- **分块结构（硬口径，2026-10-09 广哥定）**：按方法／原则**一题一块**；块外框浅蓝、块标题＝方法名＋"说/我/德/练"式单字钩子。
- **块内用虚线分上下两区**：虚线上＝正确＋我遗漏的，虚线下＝我写错的（写错项排块末，附错误原因、前缀 `×`）。

- **错漏关键词必须在图里加粗（2026-10-21 广哥定：「对于错漏的部分的重点关键词」要加粗，「这样我看起来轻松些」，以后每张图都做）**：红色（漏写）与橙色（写错）条目里的采分词，在原有 `<text>` 内就地用 `<tspan font-weight="bold">…</tspan>` 包裹；灰色（写对）条目不包；加粗**不改该档颜色（红 `#791F1F`／橙 `#993C1D`）、不改字号、不拆新行**；主文每行最多 2 段加粗，副文（关键词行）可整段加；正文一律 400。
  ⚠️ **必须用 `bold`，不许用 `500`**——中文字体普遍没有 Medium 档，`font-weight="500"` 会回落成 400，看着完全没粗（2026-10-21 广哥当场退回：「我希望的是图片中直接加粗的字体」）。

- **图顶部第一行左侧必须放得分徽标（2026-10-21 广哥定：「以后把分数写在这个生成的图片上，明显点」）**：蓝框、字号 20、固定写法 `得分 N / 10`，右侧接一行「合理区间 a ~ b ＋ 一句口径说明」。分数与正文第 1 条评分逐字一致。徽标几何值（`x=40 y=28 w=200 h=40`、图例顺延到 `y=82`、块外框 `y=110`）见 `references/chart-color-scheme.md` 第 2.5 节，照抄勿改。
