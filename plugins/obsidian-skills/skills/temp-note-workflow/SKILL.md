# 临时记录工作流（写入 + 转写 + 清空）

`<vault>\临时\临时记录.md` 是用户的**知识点暂存箱**：分析过程中随手往里攒，攒够了再一次性搬进正式笔记/总结文。
这两个动作用户**反复纠正过**，本 skill 把纠正结论固化成硬规则，执行前通读，不要凭印象发挥。

## 触发词边界(2026-09-05 用户定,写在前面防接错活)
- **"写到临时记录 / 写进临时记录 / 把这个写到临时记录"** → 本 skill,目标是 `<vault>\临时\临时记录.md`(暂存箱,用完会清 0 字节)
- **"写到临时" / "写到 obsidian"**(不带"记录"二字) → **不是本 skill**:指在 `<vault>\临时\` 目录下**新建一个 .md 文件**,走 `vault-content-summary`(格式)+ `vault-write-discipline`(verifier)
- **判据只看末尾两字**:末尾是"记录" → 写 `临时记录.md`;不是 → 在 `临时/` 下新建文件
- 拿不准就在动手前问一句,别凭印象默认成"写到临时记录"——2026-09-05 就是把"写到临时"接成了写临时记录,写错地方被用户当场纠正

## 硬规则（每条都是用户原话级纠正，违反就是返工）

1. **进临时记录 = 纯知识点，零出处引用**
   禁止出现：`vault出处:` 段、`(理论精讲XX 第N行)`、`(原话...)`、"vault 中对应位置/供对照"、"详见某笔记第N行" 等**位置提示类信息**。
   用户原话："在这种写入的时候都不要加这些。"
2. **零发挥：只写纯知识点，禁例题 / 禁步骤 / 禁考法解读**
   2026-09-02 用户原话："**临时记录里,你不要过度决定了,把什么例题 什么步骤都去掉**"。
   明确禁止自行加料以下四类（都是我"过度决定"出来的，不是用户要的）：
   - **例题 / 题面**：不写"题目原文""题目(2024下辨析题)""课后第 12 题"等题号与题面复述；节标题里也不带"(含 2024 下辨析真题)"这类题号。
   - **答题步骤模板 / 答题框架（不含数学推导）**：不写"第 1 步·判断""第 2 步·说理层一""第 3 步·总结""辨析三步得分法""判断题面 → 错误(×)"。**数学推导 / 分支讨论 / 反例属"知识点"不是"答题框架"**, 按硬规则 3 必须逐条完整写进, 不受本类限制。
   - **自己的考法解读**：禁"考点串联""易混提示""与其他节联动""本题陷阱类型""答案节奏""首答题落点""统一模型的应用"。
   - **过度讲解图**：图只写一句图名 + `![[images/x.png]]` 嵌入（**图片嵌入一律不带别名**，真源 `shared/citation-link-aliases.md`），**不逐框写"对应解读"**。
   可保留：纯定义、纯条文、纯口诀（如"三有一训练,控制影响很全面"）、图片嵌入、必要分类列举。
   反例教训：用户连续发科二辨析题截图，我每次都套"题目原文 → 三步得分法 → 易混提示 → 节联动"模板，文件膨胀到 127 行被叫停，重写后 98 行纯知识点。
3. **但知识点本身必须写全，不许缩减**
   上一条去掉的只是"出处引用"，内容该几条就几条、该有推导就有推导，**不能压成一句简述**。
   细化：聊天里展开的证明/推导必须**逐条完整**写进——不得把多步推导压成"由…得…"一句；不得省略**分支讨论**（如 $|A|=0$ 与 $|A|\neq0$ 两种情形）、**反例**（如 $A=B=E$）、**口诀**与**呼应坑**；这些都属于缩减。
4. **从临时记录搬到别的文件 = 逐条搬运全部知识点，严禁压缩**
   2026-08-29 用户纠正：把临时记录内容并入生成的总结 md 时"缩减成 1–3 行简述"是**明确违规**。
   同时**也不能照抄**临时记录里的全角标点/超长节：须改写为 vault-content-summary 合规样式（半角标点、`## 𒋙` 分组、扁平节 ≤ 9 条、超出拆子节）。
   **2026-08-31 补充（勿只挂链接）**：挂 `[[临时记录#𒋙xx|标题]]` 这类链接**不算搬运**——临时记录随后会被清空，链接必然失效，用户原话"你把临时记录总结进去吗?怎么没图?总结了也应该删掉原内容啊"。判定标准：**清空后目标文件必须仍自成一体**，靠临时记录链接才看得懂 = 没搬。
   两类易漏内容：**① 图片**——临时记录里 `![[images/x.png]]` 引用的图要一并嵌到目标文件对应条目下（缩进写 `![[images/x.png]]`，**缩进跟随目标文件既有形态**：Tab 或 4 空格、同一文件内一致，真源 `vault-write-discipline` Pre-Write Checklist #12）；**② 数学史/公式推导/子节类知识点**——常常因为"与目标主题不直接相关"被整节跳过，必须逐节清点临时记录的每个 `##`/`###` 节，确认都有归属。
5. **转写时不写"来自临时记录"这类来源标注**
   临时记录随后会被清空，标注无意义且会对不上；目标文件要**完全自成一体**。
6. **搬完主动清空临时记录为 0 字节**，不等提醒、不顺延到下次。
7. **临时记录也是 vault 文件，套 vault-content-summary 视觉格式**：`## 𒋙` 节、紧凑零空行、半角英文标点、`N. ` 后一个空格、关键词 `**加粗**`、行内公式 `$...$`、填空用 `……` 而非 `______`。
   **加粗判定以 `vault-write-discipline/references/bold-keyterm-rules.md` 为单一真源（2026-09-04 补：此前本条只写"关键词加粗"，没引判定规则，写入时凭直觉涂色、曾把答题展开整段涂粗被点名）。** 判定要点：口诀/被定义项名/并列项名/限定条件才粗，说明/过程/评价词不粗；单条加粗块：≤60 可见字者 ≤3、>60 可见字且已按硬规则 15 拆行者以 ≤5 **为基准、按整条可见字数浮动上调**(每再长约 60 字 +1 处; **2026-09-29 用户定: 上限按内容长短定**)（**按整个条目合并计、不按物理行计**）。分行缩进的单一真源见硬规则 14（vault-write-discipline checklist #14），长句拆行见硬规则 15（vault-write-discipline checklist #19）。
   **临时记录不要写空 H1 标题**——直接以 `## 𒋙` 分节开头即可（用户 2026-08-31 明确纠正：不要往临时记录写空的 `# 𒋙` 标题）。`# 𒋙主题` 那种带主题名的 H1 是给正式笔记/总结文用的，临时记录是暂存箱、会被清空，不需要也不该有空 H1；新增/追加知识点块一律用 `## 𒋙`（原因见流程 A 第 2 步），不要照搬别处的 `# 𒋙主题`。
   注意区分：**聊天回复**另按用户聊天格式（首行 ≤10 字、纯有序列表、禁 `#` 标题），别把聊天格式搬进文件。
8. **别和"聊天查找列表"混淆（2026-09-11 收敛为单一口径）**：
   - 用户没说"打开"时的**查找类回复**（"仓库里有没有 X / 本地查下 X"），末尾可附"相关 vault 笔记"列表（精确到行，**每条写成可点 obsidian:// 链接、不写裸路径**）——那是正常聊天行为。
   - **凡引用了库内内容的回复，每条落点一律写成可点 obsidian:// 链接**（2026-09-23 扩定：行 → 显示行号、标题 → `标题`、整篇 → `文章`；**不再写裸路径/纯文本出处**）；**vault 里没有对应落点时**（纯推理、无笔记可指）才不引、不硬塞。单一真源：skill `obsidian-jump-line`「回答引用一律用 obsidian:// 链接」节与用户级 MEMORY「一 每次对话都用的硬偏好」节的「**写入/修改/查看后必须附链接**」条（路径权威版见 `workbuddy-memory` 读取清单第 2 条；凡指向「`.workbuddy` 根目录那份无 `user-*-personal` 前缀的同名 MEMORY」的写法都是过期副本，勿用）。
   - **仍被禁止的**只有"本地依据 / 来源 / 详见某笔记第N行"这类**编号项**——它不是知识点内容、不该伪装成第 N 条；确需指引原文时用上面那种末尾"相关 vault 笔记"列表（**非编号项**）。
   - **⚠️ 旧口径已作废（防回潮）**：2026-08-30 曾定"纯概念 / 公式辨析类讲解回复不写 `obsidian://` 链接、改用末尾列表"，已被 2026-09-11 拍板取代，**不要照它退回"给序号→让用户说打开第N条"的老流程**。
   - **追加进临时记录时更不带这些行号出处**（见硬规则 1、2）。
9. **有图时直接以图片文件粘贴进笔记**：若知识点包含韦恩图、几何图、流程图等可视化内容，先在 vault 图片目录（如 `<vault>\images\`）生成独立图片文件（推荐 PNG/SVG，命名简洁可读），然后在笔记中嵌入 `![[images/xxx.png]]`。**不要用 raw SVG/HTML 代码或纯文字描述替代图**。
10. **"写到临时记录"的作用范围 = 最近一次回答（2026-08-30 用户定）**
   用户说"写到临时记录 / 写进临时记录"时，默认只把**紧邻其前的那一次问答**里的知识点写进去：即用户发指令前我最后给出的那一条回答。
   **严禁向前追溯**把本会话更早轮次的若干道题一并打包写入——用户原话："我说写到临时记录的时候指的是最近的回答，你之前好像把过多的内容写进去了。"
   判断方法：以用户这条指令为分界，**只取它上一条 assistant 回答**作为素材来源；更早的题即使同一小节、同一主题也不属于本次范围。
   拿不准时（例如一次追问串起多个题、或"最近一次回答"本身含多个知识点块）**先确认再写**；宁可少写一条，也不要自作主张扩大范围。
   **"最近一次回答" = 最近一个主问题引发的整段回答（2026-09-07 用户补定）**：围绕该主问题的**追问 / 质疑 / 澄清**不算新的分界，它们与该主问题同属一次范围、要一并写入；只有当话题换成**新的题 / 新的概念 / 新的文件**才算新主问题、分界随之前移，旧主问题及其讨论不再打包。判据全文见本 skill「写入内容范围」节（同文件，上文）；用户级 MEMORY 现无该节名，勿再引。
11. **解题类写入，节首第 1 条必须先把题目说清楚（2026-08-30 用户定）**
   凡是知识点源自某道具体题目，写入临时记录时，对应 `## 𒋙` 节的第 1 条先写**题目原文/题意**（已知条件、所求），再展开知识点。用户原话："你把题目是什么也补充进去"、"以后这种情况都要把题目先说一下"。
   目的：临时记录脱离聊天上下文后仍能还原是哪道题，避免只存解法缺了题面。题目条也走加粗唯一强调、半角标点，不写 `==高亮==`、不带出处行号。
   非解题类（纯概念、纯公式辨析）则不强制写题目，直接从知识点起头。
   **辨析题 / 判断题 / 选择题不写题面，直接写结论**（用户 2026-09-02 原话："临时记录里,你不要过度决定了,把什么例题 什么步骤都去掉"）——这类题的题面本身就是一句待判正误的命题，复述它正是用户说的"例题"。
   判据：**题面本身能不能直接转成一条知识点？** 能 → 直接把结论写成知识点（例："教材编写的直接依据是**课程标准**，不是课程计划"），**不写**"题目原文:…→ 判断:错误(×)"。
   只有**计算题 / 证明题**（含具体已知条件与所求、脱离题面就看不懂解法）才仍按本条保留题面第 1 条。拿不准按硬规则 2 处理（不写题面）。
12. **"写到临时记录"默认写到合适位置（2026-08-31 用户定）**
   用户说"写到临时记录 / 把这个写到临时记录"时，**默认按主题就近插到合适位置**——先 Read 全文，按主题定位最相关的既有 `## 𒋙`/`### 𒋙` 小节，插到它**紧邻处**；只有确认毫无相关主题时才在文件末尾新建节。
   **不再一律追加到文件末尾，也不再逐次问用户"放哪里"**（用户原话："以后说写到临时记录的时候，默认写到合适的位置"）。
   落位细则：本次内容是某条既有条目的补充/证明/辨析 → **紧跟该条或该小节**（例：某公式"怎么来的"的推导，插在该公式所在小节之后、下一个相关主题小节之前）；是全新主题 → 放在同主题大类附近，实在没有才末尾新建。
   顺带修正：定位时若发现既有条目有笔误（如把"不变量"误解成"等于 0"），**就地一并修正**，不必另行征求同意，修完告知用户改了什么。
13. **从临时记录总结/合并到别的文件时，目标文件的 H1 大标题一律写 `# 𒋙重难点和易错点`（2026-08-31 用户定）**
   用户原话："在把临时记录写到或总结到别的地方的时候大标题改成 重难点和易错点"。
   **适用范围**：流程 B 新建目标文件、或目标文件尚无 H1 需要补标题时；标题文本就是这七个字，**不加**课程名/章节名/日期等前后缀。
   **并入既有笔记**时若该文件已有自己的 H1，**不要**覆盖成这个标题——这条规则只管"从临时记录搬出去生成的目标文件"，不管被并入的既有笔记的原有标题。
   **不适用情形（优先级更高）**：本次任务若**点名了 PDF / 视频 / 音频等媒体源**，一律以 `pdf-to-vault-summary` 为准——H1 用**源材料的标题**、骨架照源材料原样，不使用这七个字。
   目标文件内的分节仍用 `## 𒋙`（必要时 `### 𒋙`/`#### 𒋙`），与流程 A 的体例保持一致。
   **H1 三条口径的优先级总表（2026-09-09 定，消除三个 skill 各自表述带来的歧义）**：
   ① **点名了 PDF / 视频 / 音频等媒体源** → 用**源材料的标题**（`pdf-to-vault-summary`，骨架照源材料原样）；
   ② **从临时记录搬出、新建目标文件**（无媒体源）→ `# 𒋙重难点和易错点`（本条）；
   ③ **其他生成文件** → `# 𒋙<话题标题>`（`vault-content-summary`）。
   **并入既有笔记时一律保留该文件原有 H1，不覆盖**——这条优先于上面三条。
14. **隶属关系用 4 空格缩进、并列关系分行继承缩进（2026-09-02 用户定）**
   用户原话："文字中如果有明显的隶属关系要用 4 个空格的缩进来表示,并列关系的内容分行表示,并且分行的时候要继承这些并列内容的隶属关系,就是可能要在缩进中去分行"。
   - **隶属 → `    1. ` 4 空格子列表**（禁止把子项摊平在父行里用 `,` `;` 串联）；
   - **并列 → 各自独立成行，且全部保持同一缩进量**（这就是"在缩进中分行、继承隶属关系"）；
   - 缩进是 **4 的倍数**、**不跳级**、**最多 2 级（只有 0 / 4 / 8 三档，12 空格起违规）**；
     4 空格续行表达隶属时**必须带列表标记**（`    N. ` / `    - `，**符号跟随目标文件既有体例、同文件禁混搭**，见 `vault-write-discipline` 第 14 条）或为 `![[` 嵌入；**列表项之后的无标记 4 空格续行合法**（2026-09-07 定稿：渲染为缩进线，作单行附属说明、不带编号），仅**顶层裸 4 空格无标记行**禁用（判据 = 向上回溯整段续行、段首前一行是空行 / 文档开头 / 普通正文时才是真代码块风险；**确属真风险时用 3 空格软续行，禁补列表标记**，见 `vault-write-discipline` 第 5 条 🚫 条）。超过 2 级的深层级一律**压平**：
     改写为单行 `**关键词**:**内容**`，或提升为与兄弟并列的 `N. ` 子项，不再往下钻。
   权威规则与正反例见 `vault-write-discipline` Pre-Write Checklist #14（单一真源）。
   `verify_discipline.py` 已加"缩进为4的倍数""缩进不跳级""缩进最多2级(≤8空格)"三项硬检查，违规直接 FAIL。
15. **长句必须按语义断点拆行（2026-09-28 用户定）**
   临时记录里的知识点常常是一大段口述原话，**禁止一条挤成一行长行**。判据：**单个条目可见字数 > 60 必须拆**（口径：首行 + 该条所有无标记 4 空格续行合并；删 `[[...]]`、`$...$`、`**` 本身与全部空白后计数；肉眼估 = 超过一行半）。
   - **首行必须是带标记的列表项** `N. `，其余子句写成**连续的无标记 4 空格续行**（不带 `    N. ` / `    - ` 标记——带了就变成表达隶属，违反硬规则 14）；续行只在同一条目内，下一个 `N. ` 出现即本条结束；
   - **同条目下的连续多条续行合法**（2026-09-28 用户定放开）：verifier 的 `顶层裸4空格` 一项**已于 2026-10-21 改为回溯判据、此形态不再报警**（旧判据下曾误报，属已知豁免），**不得**为消警把行并回去、**不得**给它们补列表标记；
   - 断点放在：换主语 / 换时间、"是什么"转到"怎么用"（口诀 · 判定流程 · 易错点）、出现但 · 然而 · 因此（连词跟着新行开头）、出现新的限定条件或反例；
   - **加粗密度按「整个条目」合并计、不按物理行计**：>60 可见字且已拆行的条目以 ≤5 处为基准、按整条可见字数浮动上调，≤60 字 ≤3 处；占比 ≤40% 不变。**verifier 查不到续行**（采样正则只认带列表标记的行），这条是人工自检，写完自己数一遍。
   单一真源：`vault-write-discipline` Pre-Write Checklist #19（含 5 类断点与三组 ❌/✅）与 `references/bold-keyterm-rules.md` 第 4 节（密度表）；本 skill 不复写其正文。

## 流程 A：追加到临时记录

0. **界定范围（硬规则 10）**：先确认"最近一次回答"是哪一个——只取用户指令前我最后给出的那一条回答作为素材，不回溯更早轮次。范围有歧义就先问，不要默认"本轮全部"。
1. **先读** `<vault>\临时\临时记录.md`（空文件则直接起头）：确认已有节结构、避免与既有条目重复。
2. **定位插入点（默认按主题就近插，见硬规则 12）**：先通读全文找最相关的既有分节 → 插到它**紧邻处**（相关主题小节之后；本次内容是某条的补充/证明/辨析时紧跟该条）→ 只有确认毫无相关主题时才在文件末尾新建节。**不要默认追加到末尾，也不要问用户放哪里**。
   **关键**：必须用 `## 𒋙`（与文件既有体例一致），**不能用 `# 𒋙`**——`verify_discipline.py` 的 `HEADING_RE` 只匹配 `#{2,6}`，H1 不被当作分节符，新条目会并进上一个 `## 𒋙` 节，同时触发"分标题有序列表从1重编"与"扁平节条目<=9"两个 FAIL（表现为 `lvl2 nums=[...,1,2,...]`、条目数 >9）。
2.5. **图片处理**：若本知识点含图（韦恩图、几何图、流程图等），按硬规则 9 生成图片文件到 `<vault>\images\`，然后在笔记里嵌入 `![[images/xxx.png]]`，再写文字条目。
3. **写入**：用 Edit 精准插入，保持紧凑零空行，套硬规则 1、2、3、7（纯知识点、零发挥、写全不缩减、文件体例）+ 硬规则 11、12（解题类节首写题面、按主题就近插入）。
4. **全文规整（追加后必做，校验是全文的、不是只查新加的行）**：
   转半角标点：`normalize_vault_summary.py "<vault>/临时/临时记录.md"`；
   删全文空行：用托管 Python 读文件 → 过滤 `l.strip()!=''` → 写回（零空行是硬要求，旧内容常留分节空行）。
   **⚠️ 唯一的空行例外（2026-09-10 裁决）**：`> [!NOTE]` callout 块**前**那一个空行**必须保留**（见 `vault-write-discipline` Pre-Write Checklist #1）——删空行时按"下一行以 `> [!NOTE]` 开头则保留该空行"处理。临时记录默认不写 callout；真出现时以该条为准，**不要为凑零空行把它删掉**。
5. **自检**：无出处引用、无 `______`、半角标点、内容完整未缩水。
6. **跑 verifier**（普通笔记级，只跑这一个）：
   ```bash

     "~/.workbuddy/skills/vault-write-discipline/scripts/verify_discipline.py" \
     --all "<vault>/临时/临时记录.md"
   ```

   退出码 0 才算完；有 FAIL 先修再跑。

## 流程 B：从临时记录总结 / 合并到别的文件

1. **完整读**临时记录，把知识点**逐条列出清单**（不遗漏、不压缩，条数临时记在心里或草稿里）。
2. **确定目标文件**：用户点名 → 用点名的；没点名 → 选内容最贴近的既有笔记并**并入对应节**，都不合适才新建（生成文件默认 `<vault>\临时\`，用户另有指定除外）。
3. **改写为合规样式**（不是复制粘贴）：
   - **大标题写 `# 𒋙重难点和易错点`**（硬规则 13）：新建目标文件/补 H1 时就用这个标题，七个字不改不加前后缀；并入的既有笔记已有 H1 则保留其原标题不动。
     **例外（优先级更高）**：本次任务若**点名了 PDF / 视频 / 音频等媒体源**，一律走 `pdf-to-vault-summary`，H1 用**源材料的标题**、骨架照源材料原样，不适用这七个字。

   - `## 𒋙` 节分组、编号不跨节累加、扁平节 ≤ 9 条（超出拆 `### 𒋙` 子节）——**仅本流程与普通汇总场景**；冲刺带背系列「单节超 9 条」拆**并列 `## 𒋙`**，判据 = 本次处理的是不是带背系列（权威版见教资工作区 `.workbuddy/memory/MEMORY.md`「冲刺带背系列」节）；
   - 关键词 `**加粗**`，注意粗体内边缘不能贴标点（`**麦积山**(2014)` 而非 `**麦积山(2014)**`）；**"什么该加粗"以 `vault-write-discipline/references/bold-keyterm-rules.md` 为单一真源**（口诀/术语名/并列项名粗，说明与过程不粗；单条 ≤3 块，>60 可见字且已按硬规则 15 拆行者以 ≤5 块为基准、按整条可见字数浮动上调，一律按整个条目合并计）；

## 反面案例（都真实发生过，勿重犯）

1. 追加时在末尾加了 `vault出处:` 段并标 `(理论精讲4 第9行)` → 用户："在这种写入的时候都不要加这些。"
2. 把临时记录并入总结 md 时压成 1–3 行简述 → 用户："不可缩减成 1–3 行"（须逐条搬运全部知识点）。
3. 转写时开头写"以下内容整理自临时记录"、或在条目里写"例题(临时记录)""临时记录关键提醒" → 违反"目标文件自成一体"，用户："用完内容就会删掉的，不要提临时记录这个文件"（2026-09-01）。
4. 搬完忘了清空 → 下次又搬一遍同样的内容。
5. 写入临时记录时把聊天里展开的证明（如 $|A^*|=|A|^{n-1}$ 的定义法推导，原含"取行列式→右边 $|A|^n$→讨论 $|A|$ 是否为0→结论→呼应坑"多步）压成一句"由 $A^*A=|A|E$ 两边取行列式…得…"简述 → 违反硬规则2（知识点写全不许缩减）；凡聊天里展开的证明/分支/反例/口诀都要逐条完整搬进。
6. 把聊天回复格式（禁 `#` 标题、纯有序列表）套进临时记录文件 → 文件里应正常用 `# 𒋙`/`## 𒋙` 标题（**本句只说"别把聊天的禁标题格式套进文件"这一件事；临时记录本身仍按硬规则 7 不写 H1**，两条不冲突）。
7. 追加新主题时用了 `# 𒋙主题`（正确写法是 `## 𒋙`）→ `verify_discipline --all` 报 4 FAIL：H1 不分节致新条目并入上一节，触发"跨节编号 + 扁平节 15 条"，外加旧内容原有的全角标点与分节空行；用户侧感受是"明明只加了几行为什么整个文件不合规"。正确处理：改用 `## 𒋙` + 全文跑 `normalize_vault_summary.py` 转半角标点 + 删全文空行 → 再 verify 即 ALL PASS（exit 0）。
8. 把 SVG/HTML 代码块或文字描述直接写进临时记录来表示图 → 用户 Obsidian 里无法直观查看，应先生成 PNG/SVG 图片文件到 `<vault>\images\`，再用 `![[images/xxx.png]]` 嵌入。
9. "结合临时记录总结"时只在目标 md 里挂 `[[临时记录#𒋙xx|标题]]` 链接，知识点本体没搬、图没嵌、搬完也没清空 → 用户："你把临时记录总结进去吗?怎么没图?总结了也应该删掉原内容啊 你没按 skill 来吧"（2026-08-31）。三件事必须同时做到：**逐条搬全 + 图一并嵌入 + 搬完清 0 字节**，且目标文件里不得残留指向 `临时记录` 的链接。
