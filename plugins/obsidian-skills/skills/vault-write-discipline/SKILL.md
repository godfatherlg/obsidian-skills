# Vault Write Discipline (写文件前纪律终检)

每次要把 markdown **写进 vault** (`<vault>` 任意子目录) 之前，先跑本 skill 的验证脚本，
确认 **ALL PASS** 再 `present_files`。这是把"生成内容格式纪律 + 临时文件夹纪律"从
"我记在 memory 里、但常忘执行"升级成"脚本强制拦截"的关键动作。

## 为什么是 skill + 脚本，而不是只写在 memory

memory 里的纪律是**被动**的——它在上下文里，但靠我"想起来去读"才生效，所以老忘。
本 skill 的验证脚本是**主动**的——present 前必须跑，退出码非 0 就说明有违规，逼我修掉。
机制和你已有的 `vault-content-summary/scripts/verify_vault_summary.py` 完全一致，只是覆盖范围不同。

## 与 vault-content-summary 的分工（重要）

- `vault-content-summary` 的 `verify_vault_summary.py`：负责**汇总风格**专属硬规则
  （`## 𒋙` 标题、`pdf#page=` 来源链接、别名白名单、连续同集合链接合并等）。
- 本 skill 的 `verify_discipline.py`：负责**所有生成文件通用**的纪律 + 临时文件夹纪律。
- **汇总风格文件**（报告/汇总/总结）：present 前两个脚本都跑。
- **普通笔记**（讲义补充、知识点插入、临时记录等）：只跑本脚本即可。

两者都通过才 present；任一 FAIL 都先修。

## Pre-Write Checklist（每次写文件前心里过一遍）

1. **紧凑零空行**：节与节、条与条之间不插装饰性空行；仅 H1 标题单独占首行；无引言段。
   唯一例外：`> [!NOTE]` callout 块前允许且必须留**一个**空行。
2. **有序列表 `N. ` 后恰一个空格**，不得双空格 / tab。
3. **半角英文标点**：`, . ; : " " ( ) ! ?` 代替全角 `，。、；：（）！？`。`…` 与 `·` 豁免；
    **破折号 `—`(em dash) 与中文引号 `“”` 同属全角, 会被判 FAIL:** 中文里想断句改用 `--` 或直接换成逗号/冒号；
   `[[ ]]` / `![[ ]]` 内目标文本不动；markdown 行号链接 `[N](obsidian://adv-uri?...&line=N...)`（显示文字=目标行号数字）的
   URI 内部（`%2F`/`&`/`=`/路径中文）同样不动，不作标点或下划线处理（见 `shared/citation-link-aliases.md` 的「Line links」节）。
4. **bold 内边缘标点安全**：`**` 紧贴引号会失效，写成 `文字 **"引号内"** 文字`
   （`**` 前后各留半角空格）。纯 `**中文**` 紧贴中文安全，无需空格。
   **示例里的引号只为演示 flanking 位置**：中文全角引号 `“”` 本身属第 3 条的禁用全角标点（verifier 的 FW_PUNCT 含它，写了直接 FAIL），
   写作中一律改用**半角引号** `"` 或书名号《》，不要用这个示例里的全角引号。
   **强调手段只有加粗一种（2026-08-30 用户定）**：表达重点一律用**加粗**，但要分清加粗的**两种载体**，混用是高频错法：
   - **文本加粗**用 Markdown `**...**`：中文/英文术语、限定条件、结论词、口诀等纯文字重点。
   - **公式内符号加粗**用 LaTeX 数学命令 `\boldsymbol{...}`：向量、矩阵、希腊字母、需强调的公式片段都靠它（如 `\boldsymbol{A}`、`\boldsymbol{\alpha}`、`\boldsymbol{y=x}`），由渲染器在数学模式内处理，**用户 vault 里此命令即为"公式加粗"的规范写法**。
   **绝不能用 `**$...$**` 把「整条公式」包进 Markdown 加粗**（加粗块首尾就是 `$`，如 `**$x>0$**`）——既越界（公式加粗有专门数学命令）又极易触发第 16 条的 flanking 渲染断裂。
   **但加粗文字中间夹带公式是允许的，且必须写成 `$\boldsymbol{...}$`（2026-09-07 用户定）**：正确写法 `**证 $\boldsymbol{0<p\le1}$ 发散 (下界放缩)**`；因为用户的 CSS 只认 `\boldsymbol{}` 来把公式染粗，加粗块里的公式若写普通 `$...$`，渲染出来就是「粗体文字中间夹一段细体公式」，视觉断裂。即：**外层粗文本用 `**...**`，夹在其中的公式一律用 `$\boldsymbol{...}$`**，两者配套。
   **严禁 `==高亮==`**（Obsidian highlight 不在用户规定内，属自行添加的违规样式）。
   **归属定性（2026-09-10 用户明令）**：`==高亮==` 是**用户人工画重点的专属标记**，AI **只能读、不能写**；任何情况下（包括润色、补充、搬移知识点的顺带动作）都**不得**给新内容加高亮。用户原话："以后你应该不能用高亮的, 高亮是我人工画重点的"。
   **例外（2026-09-10 用户点名，永久例外不进收敛队列）**：用户明确要求「把某文件里**他自己标的** `==高亮==` 搬到另一文件的对应处」时从其令
   —— 那是对**用户人工标记**的搬运，不是 AI 自行添加样式；搬进目标文件后同样视为用户人工标记，**不回改、不因本条删除**。
   判据是"本次用户有没有点名要搬高亮"，不是文件类型。搬运时的落法（可复用）：目标行里有对应文字→就地 `==包住==`；
   没有对应文字（讲师口述的口诀/技巧）→ 把这条知识点以 `==片段==` 追加到该题行尾、链接之前；
   **目标文件里根本没有这个考点的题时→跳过并在回复里说明，不硬塞**。
   **反面教训（2026-09-10 17:13）**：给科二教育学 207 条补子注释时，顺手把新写的对照句与口诀都套了 `==`，被用户当场纠正"这次就算了，以后不能用高亮"。同一次写入里**其余 `==` 若是用户原有的必须保留**（如 207/209 条原有高亮），**只清理自己新增的那些** —— 判定靠读原始版本比对，不能整篇 `replace('==','')`。
   **同理严禁 LaTeX 的 `\boxed{}`（2026-09-06 用户定）**：用户片段 `公式高亮-Temml-boxed.css` 专门把 `\boxed{x}` 染成与 `==高亮==` 同色 `rgb(255,236,153)`，即**用户的人工高亮工具**；它渲染出来就是带框色块，视觉效果等同高亮。属用户人工标记专用手段；**新写内容一律写普通公式 `$...$`**，强调公式符号改用 `\boldsymbol{}`，强调公式前的名称或后的限定条件改用 `**` 粗文本。
   旧文件里已有的 `\boxed{}` 与 `==...==` 一样不回改。
   **已脚本化（2026-09-27）**：PostToolUse hook 把本次新增文本（Edit 的 `new_string` / Write 的 `content`）经 stdin 交给 verifier 单独检查——Edit 命中 `==` / `\boxed` 判 **FAIL**（new_string 就是纯新增, 零误伤）, Write 判 **WARN**（整篇 content 无从区分 AI 新加的与用户原有的人工标记, 需人眼确认）。
   **为什么只查新增不整文件扫**：全库 1710 个 md 里 546 个含 `==`（5097 处）、36 个含 `\boxed`（693 处）, 整文件 FAIL 会判死三分之一 vault。
   **外部自动注入（2026-09-07 反复出现）**：vault 内某自动化（linter/宏，源头待查）会给**新写入的行**自动套上 `==高亮==` 与 `\boxed{}`（当日三度出现）；按第 13 条写入后重读文件时，发现新增行被套这两个标记须一并还原为普通公式/文本。
   **⚠️ 本条只管加粗的「排版安全」；「什么该加粗」的判定规则见本清单第 15 条（单一真源：
   `references/bold-keyterm-rules.md`）。**
5. **缩进续行体例**（2026-09-07 用户定稿；2026-09-24 补「补充内容解释上一行必须缩进」）：**列表项（`N. ` / `- `）之后的无标记 4 空格续行合法**——用户环境中渲染为缩进线（tab 线），用于"一条附属一个说明"的单行补充（不带编号）；**同一条目下可连续多条**——按第 19 条「长句必须按语义断点拆行」产生的连续续行属本条放行范围（2026-09-28 用户定放开，详见下面情形 B）。
   **🔴 首行即缩进（2026-09-29 用户定，最高优先级）**：**AI 本次新加入的文字，第一行就必须缩进**，**严禁顶格起头**。判据是语义性的：不缩进读者就无从判定它在注释上一行（用户原话："我的重点在于你加入时第一行没缩进，如果不缩进，我就不能认为你是在注释上一行。"）。三种合法落法：① **整体缩进**——新增内容常是"某个已写好内容的补充"，直接缩 4 空格即可，**可以不加任何列表标记，但必须缩进**；② **小标题式**——新增内容自带小标题时，把小标题做成**子项**，列表符按第 14 条「标记类型跟随文件体例」走（**通篇有序的文件用 `    N. `**，无序文件才用 `    - `），下面各行缩进为其续行；③ **前一行是列表项且新增是解释它** → 无标记 4 空格续行；**前一行不是列表项** → 带标记 `    N. `/`    - `（**符号按第 14 条跟随目标文件体例**，不是随手二选一）。
   **🚫 绝对禁令：禁止改动用户已写好的内容（2026-09-29 用户当场纠正）**：本条的**唯一对象是"本次 AI 新加入的文字"**，**不授权**顺手去"规范"既有行的形态——用户原有行哪怕是"引导句 Tab 顶格无标记"这种非常规形态，也**一律原样保留**：**不得给它补 `- ` 标记、不得改它的缩进量、不得把它并入别的行**。用户原话："你不应该改我已经写好的东西。因为你加入的一般是某一个已经写好的内容的补充，所以一般只需要缩进写就行。"（反面教训：2026-09-29 把 `冲刺班/科二/最后一遍疯狂刷题科目二教育学单选题.md` 的顶格引导句改成了 `- ` 无序列表项，被当场纠正、已回滚。）
   **⭐ 补充 / 注释内容解释上一行必须缩进（2026-09-24 用户定）**：凡"补充到某行下方、且旨在解释 / 限定 / 举例上一行"的内容（典型如某题行下的 `注:...` 分类说明），一律视为**隶属于上一行**，必须缩进——前一行是列表项（`N. `/`- `）时用**无标记 4 空格续行**；前一行非列表项时带 `    N. `/`    - ` 标记（**符号按第 14 条跟随目标文件体例**；或 3 空格软续行）。**绝不允许写成顶层裸行、与上一行同缩进平铺**。此条是行为纪律，verifier 只能查已写缩进合不合规、查不出"该缩进却没缩进"，写入前须自检：后加的内容是不是在解释前一行？是 → 缩进（见第 14 条 隶属体例）。隶属层级表达**必须用**带标记的 4 空格**（`    N. ` / `    - `）或 `![[` 图片嵌入——**无标记 4 空格续行只是排版续行，不表达隶属**（见第 14 条）。**顶层裸 4 空格无标记行仍禁止**（判据 = 向上回溯整段续行后，段首前一行是**空行 / 文档开头 / 普通正文**时才是真代码块风险；段首前一行是列表项则合法），确属真风险时用 **3 空格**（对齐内容起点）软续行，**禁止用补列表标记来消警**（见下方 🚫 条）。
   **连续多条无标记 4 空格续行（2026-10-21 已从"必然 FAIL"改为"不再误报"，下面是更新后的口径）**：verifier 第 5 项的判据在 **2026-10-21 广哥拍板后已改为「向上回溯整段续行」**——`verify_discipline.py` 会从该行向上跳过连续的无标记缩进行，若落点的**上一行是列表项（`N. ` / `- `）就整段放行**（旧判据只比对 `lines[i-1]`，所以同一条目下第 2 条起的续行必然误报）。⇒ **"列表项 + 多条无标记续行"这种形态现在零报警，属于完全合法的标准写法**，不需要合并、不需要补标记，也不需要当豁免人工忽略。仍会报的只有真风险：段首前一行是空行 / 文档开头 / 普通正文。下面两种情形保留作历史处置说明，**正常已不会再触发**：
   - **情形 A（搬用既有源件、用户没点名）→ 默认仍按老办法合并**：（实例：`冲刺班/科二/最后一遍疯狂刷题科目二教育学单选题.md` L223 / L308）**把第 2 条并入第 1 条**（行尾加一个空格后拼接）即可通过，内容一字不减；**不要**为过检去删句子。
   - **情形 B（本次是 AI 自己按第 19 条拆长句）→ 默认合法，属已知豁免**：此形态是为"长句按语义断点拆开"而产生的**有意形态**，合并回去会让长条目重新不可读，补列表标记则会把它讹说成隶属（违反第 14 条）。**不得为消警把行并回去，也不得给它们补 `    N. ` / `    - ` 列表标记**；旧判据下 verifier 报的 `顶层裸4空格` 属**已知豁免**（按第 8 条那类看待，**2026-10-21 起该形态已不再报警**），其他检查项照常必须零 FAIL。处置与下面 2026-09-17 那条完全同款，两条的关系见第 19 条末段。
   **⚠️ 例外（2026-09-17 用户点名，永久例外不进收敛队列）**：**判据 = 本次用户有没有点名要这种形态**。用户明确选中"无标记 4 空格续行"（同一条目下多条注释行）时从其令——AI **不得为消警擅自把两条合并成一行，也不得给它们补列表标记**；此时旧判据下 verifier 报的 `顶层裸4空格`（实例：`冲刺班/科二/最后一遍疯狂刷题科目二教育学单选题.md` 207 条下 L228 / L229 与另一处 L314 共三处；**2026-10-21 改回溯判据后已零报警**）属**已知豁免**，按第 8 条「扁平节≤9」同类看待。理由：这些行在用户环境渲染为缩进线，是 `207.` 条下多条并列注释的**有意形态**，合并成一行会让长注释不可读；而消警的替代写法（3 空格软续行）视觉缩进浅一格、与同组其余行不齐。上一条"把第 2 条并入第 1 条"**只适用于用户没有点名**、由 AI 自行搬运源件时的默认修法。**⚠️ 本例外与第 19 条是并列两条、互不覆盖**：判据不同（本条 = 用户点名保持原样；第 19 条 = 自写长句按 >60 可见字必须拆），区分见第 19 条末段。
   **🚫 禁止为消掉 verifier 的 `顶层裸4空格` 报警去补列表标记（2026-10-21 广哥当场退回，硬约束）**：广哥原话「这里不是顶层啊，不用加 `-`」。判据一句话——**看这段缩进的第一行，它的上一行是谁**：是列表项（或本身已是同一段续行）⇒ 整段就是这个列表项的内容，一律用**无标记 4 空格**；补 `    - ` / `    N. ` 会把它讹说成"隶属的子项"（违反第 14 条），渲染上也把一段连续注释切成另一套列表体系。只有段首前是**空行 / 文档开头 / 普通正文**才需要处理（改 3 空格软续行）。**事故记录（2026-10-21，`冲刺班/科二/最后一遍疯狂刷题科目二教育学单选题.md` 378 题下 5 条注释）**：看到脚本报 FAIL 就照报错文案补了 `-`，被当场退回；根因是**脚本报错文案当时写着"或加列表标记"**，而它又只看紧邻前一行。⇒ 该文案与判据已于同日一并改写，两处都不再误导。
   **与 `pdf-to-vault-summary` 规则 10 的「3 空格软行」同源（2026-09-10 合并口径）**：两者都是**不表达隶属的排版续行**，都**不参与**第 14 条的「4 的倍数 / 不跳级 / 最多 2 级」检查；p2v 那条只是它在"扁平节超 9 条且无可拆子标题"时的兜底合并用法，**不是第二套规则**，别把两处当成冲突。
6. **无 `\![[` 转义**：写完后复查嵌入链接前是否多了反斜杠，有则只去掉那个 `\`（勿动公式里的 `\sin` 等）。
7. **分标题有序列表从 1 重编**：不同 `##` / `###` 下的有序列表各自从 1 开始，不可跨标题连续累加。
   **搬运/摘抄多处列表块时按「节」重编，不要逐块重编（2026-09-11 踩坑）**：verifier 按节收集编号并要求
   `nums == [1..n]`；若循环里对**每个块**各调一次重编函数（计数器在函数内清零），每块首行都会写成 `1.`，
   报错形如 `lvl2 nums=[1, 1, 1, ...]`。正确做法：**先把整节要写的行拼成一个列表，再对整节一次性重编**。
8. **扁平节条目 ≤ 9**：超出用子标题拆分。
   **例外（2026-09-10 用户定，永久例外不进收敛队列）**：**判据只有一条——本次用户有没有点名要求"不分标题、整篇平铺 1-N 连续编号"**（点名即从其令）；
   **不是文件名、也不是"刷题类"这个题材**。**文件名会腐**：2026-09-10 当日「最后一遍疯狂刷题」系列就先后发生过改名与删除，

14. **⭐ 隶属 / 并列 缩进体例（2026-09-02 用户定，最高优先级排版规则）**：
    **文字中凡是存在明显的隶属（从属、父子）关系，一律用 4 空格缩进表示隶属；并列（兄弟）关系的内容各自分行表示，
    且分行时必须继承这些并列内容所共有的隶属关系——即在缩进之中再分行。** 三个硬约束：
    - **隶属 → 4 空格**：子级内容相对父级右移 4 空格，且**必须带列表标记** `    N. ` 或 `    - `
      （无标记 4 空格续行仅在前一行是列表项时合法、且**不表达隶属**——它只是排版续行，见第 5 条；顶层裸缩进会渲染成代码块）。
    - **⭐ 标记类型跟随文件体例（2026-10-20 广哥当场纠错，硬约束）**：上面那个"或"是**两个体例各用其一**，不是随手二选一——**目标文件通篇 `N. ` 有序列表，子项就必须用 `    N. `；通篇 `- ` 无序，才用 `    - `**；混杂文件按该条目所在小节的主用体例走。**同一文件内禁混搭**：混搭会在渲染上把从属块切成另一套列表体系，读者看不出它是上一条的子项。原话："这种情况不要用 `- ` 这个啊。"（实例：`冲刺班/科二/26下 心理学材料分析重点带练.md` 通篇有序，2026-10-20 曾误用 `    - ` 被退回）

    - **并列 → 分行同缩进**：同一父级下的兄弟项各自独立成行，且**全部保持完全相同的缩进量**——
      这就是"在缩进中分行、并继承隶属关系"的落法。禁止把兄弟项挤在同一行用 `；` 串联了事。
    - **层级递进 4 空格为一档，且最多 2 级**：每加深一层隶属关系再加 4 空格，

16. **⭐ 加粗 flanking 配对 / 渲染断裂（2026-09-03 用户定）**：CommonMark 规定
    **开启 `**` 的右侧必须非空白**（left-flanking）、**闭合 `**` 的左侧必须非空白**（right-flanking）。
    任一不满足 → 该 `**` 不被当作定界符，配对整体错位，Obsidian 会把中间一大段（甚至跨到下一对 `**`）
    一起加粗，视觉表现是「**前段粗、后段没粗**」「**冒号后整段被粗**」——渲染断裂。
    脚本第 11 项已加 **FAIL** 检查：按行内出现顺序交替定角色（第 1/3/5 个 = 开启，第 2/4/6 个 = 闭合），
    开启查右邻字符、闭合查左邻字符，任一为空白即 FAIL 并打印行号与序号。
    **⚠️ 已废弃的错误判定（勿复用）**：初版用「行内 `**` 出现**奇数次**」判定，
    **完全抓不到本类 bug**——坏写法里 `**` 恰好出现偶数次（4 次），只是 flanking 错位。
    **典型坏写法与正写法**（同一份文件实测 16 处，全部是「中文右括号 + 空格 + 闭合 `**`」这一种姿态）：
    - ❌ `**可乘性 (易错点) **: $a>b...$` ✅ `**可乘性 (易错点)**: $a>b...$`
    - ❌ `**补充例题 (交集) **: ...` ✅ `**补充例题 (交集)**: ...`
    - ❌ `**$|ax+b|\leq c$ 型 ($c>0$) **: ...` ✅ `**$|ax+b|\leq c$ 型 ($c>0$)**: ...`
    **不误伤的既有安全写法**（脚本实测通过，勿改）：`文字 **"引号内"** 文字`（开启 `**` 左侧是空格但
    右侧是引号非空白 → 合法）、`**术语**, 说明`、`**术语**: 说明`。
    **排查流程（人工）**：① 阅读模式看加粗是否「前段粗后段没粗」；② 切源码模式逐个数该行 `**`，
    按 1起/2闭/3起/4闭 交替定位，看闭合 `**` 左边是不是空格；③ 删掉那个空格，让 `**` 紧贴 `)`。
    **批量修法**（同文件多处时）：`re.sub(r'\) \*\*:', ')**:', raw)` 一次清干净，
    改完重跑 `verify_discipline.py --all <file>` 确认新检查项 OK。
    **完整规则与对照表见 `references/bold-keyterm-rules.md` 第 9 条。**
