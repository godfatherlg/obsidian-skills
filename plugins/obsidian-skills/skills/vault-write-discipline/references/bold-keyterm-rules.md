> **单一真源 (single source of truth): 本文件。**
> `vault-write-discipline` Pre-Write Checklist #15 与 `vault-content-summary` Checklist #10 都引用本文; 若表述冲突, **以本文为准**。
> 制定: 2026-09-03, 用户要求"针对性写个具体的如何判断重点的规则"。
> 适用: 任何**写进 vault (`<vault>`) 的 markdown**——汇总、笔记、插入既有文件的补充内容、临时记录, 一律适用。
> 前提: 强调手段**只有 `**加粗**` 一种** (2026-08-30 用户定, 严禁 `==高亮==`); 本文只解决"**什么该加粗**", 排版安全 (标点不得贴 `**` 内侧) 见 checklist #4。

## 0. 一句话原则

**加粗是「扫读锚点」, 不是「重要程度涂色」。**

合格标准只有一条: **读者只读加粗的字, 能还原这条笔记 80% 的骨架**。
- 读加粗还原不了骨架 → 加粗加错了位置 (加粗了说明, 漏了术语)。
- 加粗连成一片黑 → 等于没加粗, 删掉一半。

由此推出加粗的**唯一功能**: 让眼睛在扫读时能**跳过说明、直接命中名词性要点**。凡是不承担这个功能的加粗, 都是噪音。

---

## 1. 判定流程: 三问过滤 (按顺序过, 全过才加粗)

### 问 1 · 删掉它, 这句话还有信息吗?
- 删掉后句子仍完整、仍讲得通 → 它是**说明/修饰** → **不加粗**。
- 删掉后这句话就空了、站不住 → 它是**要点** → 进问 2。

> 例: "教学原则是**根据**一定的教学目的**和**对教学过程规律的认识而制定的"
> 删掉"根据/和", 句子照样成立 → 不加粗。

### 问 2 · 它是「名词性要点」还是「过程性文字」?
- **名词性要点** → 加粗: 术语、专名、分类项名称、定理名、结论词、限定条件、数字、口诀。
- **过程性文字** → **不加粗**: 动作、理由、解释、举例、推导、步骤、评价、过渡。

> 判据: 能在它前面加"所谓……"或能做词典词条的 → 名词性要点; 只能做谓语/状语的 → 过程性。

### 问 3 · 同一层级里它够「稀缺」吗?
- 同一节里, 若加粗词已占该节可见文字的**三分之一以上** → 说明阈值放宽了, **删掉最不关键的那一半** (优先删说明性、重复性、通用高频词)。
- 加粗的价值来自**对比**: 满页都粗, 就没有粗。

## 2. 必加粗白名单 (7 类, 命中即加粗, 不必再过三问)

1. **被定义项** (加"名", 不加"定义内容")
   `**因材施教**:指教师从学生的实际情况出发……` — 只粗"因材施教"。
2. **并列分类的各项名称** (每项名称加粗, 各项说明不加粗; 并列项须分行同缩进, 见 checklist #14)
   ```
   1. 德育方法:
       1. **说服教育法**:通过摆事实, 讲道理……
       2. **榜样示范法**:以他人的高尚思想……
   ```
3. **结论核心词** (定理名 / 判定结论 / 唯一性表述)
   `**有且只有**一条直线……`, `**充要条件**是……`, `**洛必达法则**`
4. **限定条件** (易错前提, 最该粗的一类——丢条件正是丢分点)
   `**非零**向量`, `**n 阶**行列式`, `**不同行不同列**的 n 个元素`, `**可逆**矩阵`, `**闭区间**上连续`
5. **口诀 / 记忆词** (整条口诀加粗, 或括注里加粗)
   `三有一训练, 控制影响很全面`, `(口诀: **奇变偶不变, 符号看象限**)`
6. **数字型考点** (年份 / 条数 / 数量 / 次数 / 比例)
   `**1985** 年颁布`, `**四**个基本要素`, `**3** 种基本形式`
7. **反向 / 否定词** (易错点, 只粗那个否定词本身)
   `**不**是……而是……`, `**无**实数根`, `**不能**直接相加`, `**除外**`

## 3. 不加粗黑名单 (8 类, 命中即不加粗, 即便主观觉得重要)

1. **整句 / 整行** — 一条被一对 `**…**` 全包裹 = 没有锚点 = 违规 (脚本会直接 FAIL)。
2. **连接词 / 语气词 / 介词** — 因此, 所以, 也就是说, 通过, 在……下, 首先, 其次, 总之, 可见。
3. **说明 / 解释 / 理由 / 举例** — "例如""比如""是因为"后面的内容一律普通字。
4. **推导过程 / 计算步骤** — 中间变形、移项、代入, 全不粗; 只粗首末的结论名与限定条件。
5. **出处 / 页码 / 普通文件名** — 链接本身已视觉突出, 再粗是双重视觉噪音。
6. **本节标题里已出现过的词** — 标题已经是锚点, 条目里重复粗它不增加信息 (例: `## 𒋙德育原则` 下的条目, "德育原则"四字不再粗)。
7. **通用高频词** — 教学, 学生, 教师, 方法, 特点, 意义, 原则, 内容, 过程, 发展, 关系。**例外**: 当它是本条的被定义项时可粗 (如 `**教学**:指……`)。
8. **评价词本身** — "重要""关键""注意""易错"这类词**不粗**, 粗它**指向的内容**。
   BAD: `**注意**, n 必须为正整数` → GOOD: `注意, **n 必须为正整数**`

## 4. 密度上限 (可量化, verify_discipline.py 会查)

| 维度 | 上限 | 超限处理 |
| --- | --- | --- |
| 单条加粗块数 (**≤60 可见字** 的短条目) | ≤ 3 处 | 第 4 处起降级: 删掉, 或拆成新条目 |
| 单条加粗块数 (**>60 可见字**、且已按 checklist #19 拆成多行的条目) | ≤ 5 处**为基准**, 整条每再长约 60 可见字可再加 1 处 (**2026-09-28 用户定放宽至 5, 2026-09-29 再定: 上限按内容长短浮动, 见本节下方⭐段**) | 超出浮动上限 → 先删说明性加粗, 再按 checklist #14 拆成带标记子列表 |
| 单条加粗字数占比 (仅查 ≥30 字的条目) | ≤ 40% (**不变**) | 超过 → 整条在涂色, 只保留术语与结论。短条目 (术语名 + 并列项) 占比天然偏高, **不算违规** |
| 单节平均加粗块数 (仅查 ≥5 条的节) | ≤ 3.5 块/条 (**2026-09-28 同步放宽, 原 2.5**) | 术语清单每条 1 块属正常; 超标 = 把说明也粗了 |
| 单节加粗条目占比 | ≤ 70% (**写作自律, 脚本不查**) | 术语笔记本就每条都有术语名, 80%~90% 也常见, 不必强行削减 |
| 整条被一对 `**` 包裹 (≥15 字) | 0 容忍 (**不变**) | 直接 FAIL, 必须拆 |

**⭐ 放宽的适配条件 (2026-09-28 用户定)**: 上面那个 ">60 可见字以 ≤5 处为基准" **只有在先按 checklist #19 做了拆行之后才成立**——没拆行的超长条仍按 ≤3 处判, 且它本身已违反 checklist #19。**不得反过来拿"我今天可以用到 5 处"当不拆行的理由。**
**⭐ 密度的计数单位是「条目」不是「物理行」(2026-09-28 用户定)**: 一条 = 首行 `N. ` + 它自己的**所有无标记 4 空格续行**, 密度按**合并后的整条计一次**, **不是**每行各计一次。理由: checklist #19 允许一条拆成若干续行, 若按行计, 一条拆三行就会变成"每行 ≤5 处 ✓"而整条粗了 12 处, 直接毁掉扫读锚点。**占比 ≤40% 的分子分母同样是整条合并后的数字。**
**⭐ 上限按整条可见字数浮动, 不是固定两档 (2026-09-29 用户定)**: ≤60 可见字 ≤3 处、>60 可见字且已拆行者以 ≤5 处为基准, **此后整条每再长约 60 可见字可再加 1 处**。实例: 整条约 260 可见字、拆成 10 个续行的条目粗 7 处属合规 (2026-09-29 科一刷题笔记 133 题技巧行: 教师义务 / 强制即侵权 / 必侵权 / 带薪休假权 / 工资照发 / 补课违规 / 培训合法)。**放宽的只有"块数"这一维, 三条硬约束不放宽**: ① 仍按**整个条目合并计**、不按物理行计 (见上条); ② 整条加粗占比仍 ≤40%; ③ 粗的必须全在白名单内, 说明 / 过程 / 评价词一个都不许混进来。最终裁决回到 0 节: **只读加粗能还原该条 80% 骨架、且没连成一片黑**。
**⚠️ 脚本口径已滞后于本节 (本次用户定不改脚本, 2026-09-28)**: `verify_discipline.py` 的阈值仍写 3 与 2.5, 未跟随本节上调。由此产生的 `单条加粗块<=3(WARN)`(第 4~5 处) 与 `单节平均加粗块<=2.5(WARN)`(3.5 以内) 属**已知豁免**, 按 checklist #8 那类已知豁免处理——**不必为消警删掉合法的第 4~5 处加粗**; 前提是三条同时满足: ① 该条目已按 checklist #19 拆行; ② 整条合并后占比 ≤40%; ③ 加粗的都是白名单里的内容 (说明 / 过程 / 评价词没混进来)。三条缺一 → 仍按规则删或拆。
**更严的事实**: verifier 的加粗采样正则是 `^ *(\d+\.|[-*]) +(.*)$`, **只认带列表标记的行, 无标记续行完全不进统计**——它既拦不住"续行里涂了半行", 也测不准"整条合并密度"。**本节所有密度判据都是人工自检, 写完自己数一遍, 不要指望脚本兜底。**

**另外一条体感检查**: 连续 3 条都"只有加粗、没有说明文字" → 这一节被压成了提纲, 该补的不是更多加粗, 而是说明句。

**白名单与密度上限冲突时的裁决 (2026-09-07 用户定)**: 白名单第 2 类并列项名天然密集 (如 6 个德育途径各 1 粗), 与"单条 ≤3 / ≤5 块为基准、按整条可见字数浮动上调"(见上表) 冲突时**以拆条目解决**——把并列项写成父条目下 4 空格子列表 (checklist #14), 父条与每个子条各自计密度, 每条自然回到 ≤3; **不得用"删掉项名不粗"来凑密度**, 那会丢掉扫读锚点。

## 5. 推荐写法: 一条之内只粗三类位置

```
1. **术语名**:定义说明文字(不粗), 分 **A** / **B** / **C** 三类(并列项粗), 口诀: **xxx**
```

即: **名 / 并列项 / 口诀** 三处可以粗, 其余一律普通字。
一条写完若发现加粗超过了第 4 节的分档上限 (短条目 4 处 / >60 可见字且已拆行的条目 6 处), 自检方向依次是: 是不是把"说明"也粗了 → 是不是还没按 checklist #19 拆行 → 是不是该按 checklist #14 拆条。

## 6. 分场景细则

### 6.1 数学 (本工作区主力: 教资科三 / 考研高数)
1. **公式本身不粗**(即**禁止**用一对 `**` 把整条 `$...$` 公式包起来 —— 既越界又必触发 #9 的 flanking 断裂), 粗公式**前面**的名称与**后面**的限定条件: `**辅助角公式**: $a\sin x+b\cos x=\sqrt{a^2+b^2}\sin(x+\varphi)$, 其中 **$\boldsymbol{\varphi}$ 由点 $\boldsymbol{(a,b)}$ 所在象限确定**`。
2. **定理三件套**: 定理名粗、条件粗、结论粗, 中间推导不粗。
3. **易错限定词必粗**: 非零, 可逆, 至多, 唯一, 当且仅当, 充要, 充分不必要, 收敛, 闭区间, 可导。
4. **反例 / 边界粗**: `**x=0 处不可导**`, `**n=1 时退化**`。
5. **粗文本中间夹带的公式一律写 `$\boldsymbol{...}$`** (2026-09-07 用户定, 理由与规范写法见 SKILL.md「加粗的两种载体」条): 用户的 CSS 靠 `\boldsymbol{}` 把公式染粗, 写普通 `$...$` 会出现「粗体夹细体公式」的断裂, 例如 `**证 $\boldsymbol{0<p\le1}$ 发散 (下界放缩)**`。

### 6.2 文科条文体 (科一 / 科二)
1. 法律条文: 粗**主体 + 情形**, 不粗"应当/不得"以外的表述; 但"**不得**""**应当**"作为义务词**要粗**。
2. 人物 - 理论配对: 两边都粗, 中间的连接用**半角 -** (全角破折号 `—` 属禁用全角标点, 写进正文直接 FAIL, 见 SKILL.md #3): `**皮亚杰** - **认知发展阶段论**`。
3. 年份 + 文件: 粗年份与文件名, 不粗"颁布/通过/修订"。

### 6.3 中医 / 理疗笔记
1. 证型名、方剂名、穴位名、手法名 → 粗。
2. 症状描述、操作过程、力度与次数说明 → 不粗 (次数属"数字型考点"时可粗)。
3. 禁忌与适应症的**否定词**必粗: `**禁**用`, `**慎**用`, `**不宜**`。

## 7. 常见错误对照

| BAD | GOOD | 原因 |
| --- | --- | --- |
| `**德育过程的基本规律是……**` (整句粗) | `德育过程的基本规律: **知情意行统一发展**` | 整句粗 = 无锚点 |
| `**教学**是**教师**的**教**和**学生**的**学**` | `**教学**:教师的教和学生的学` | 通用词滥粗; 只粗被定义项 |
| `**说明**: ……` | `说明: ……` | 评价词 / 引导词不粗 |
| `**洛必达法则**(用于求极限)` | `**洛必达法则**:用于求 **0/0 型**与 **∞/∞ 型**极限 | 括注外移 (见 #4 标点规则), 结论型限定粗 |
| 一条内粗了 6 处且**没拆行** | 先按 checklist #19 拆行再算: 拆行后仍超出「按字数浮动的上限」→ 按 checklist #14 拆成带标记子列表 | 密度超限; 注意 >60 可见字又没拆行的条目按 ≤3 判, 不享受浮动放宽那一档 |

## 9. 加粗 flanking 配对 / 渲染断裂 (2026-09-03 用户定)

> 这是 markdown 加粗的**语法层面**问题, 跟"什么该粗"无关——不管粗的是术语还是说明,
> 只要 `**` 的 flanking 不成立, 渲染**必定断裂**。

### 9.1 根因: CommonMark 的两条 flanking 规则

| 角色 | 要求 (必须满足, 否则该 `**` 不被当作定界符) |
| --- | --- |
| **开启 `**`** (行内第 1/3/5 个) | 其**右侧**字符必须**非空白** (left-flanking) |
| **闭合 `**`** (行内第 2/4/6 个) | 其**左侧**字符必须**非空白** (right-flanking) |

一旦某个 `**` 失去定界符资格, 配对就整体错位: Obsidian 会把中间一大段 (甚至跨到下一对 `**`)
一起加粗, 视觉表现是「前段粗、后段没粗」「冒号后整段被粗」, 同时行首行尾多出孤立的 `**` 字面星号。

### 9.2 坏写法与正写法 (来自 `理论精讲-高中数学知识1(高中).md` 真实事故, 该文件共 16 处)

| 坏写法 (渲染断裂) | 正写法 |
| --- | --- |
| `**可乘性 (易错点) **: $a>b...$` | `**可乘性 (易错点)**: $a>b...$` |
| `**补充例题 (交集) **: ...` | `**补充例题 (交集)**: ...` |
| `**例题 (分子恒正) **: ...` | `**例题 (分子恒正)**: ...` |
| `**$|ax+b|\leq c$ 型 ($c>0$) **: ...` | `**$|ax+b|\leq c$ 型 ($c>0$)**: ...` |
| `**第四步--代入比较 (端点法) **: ...` | `**第四步--代入比较 (端点法)**: ...` |

**规律**: 全部是「**中文右括号 `)` + 一个空格 + 闭合 `**` + 冒号**」这一种姿态。
作者本意是粗"可乘性"+"易错点"两个分立标签, 但 markdown 没有"两个独立粗体块紧邻"的写法,
只能用一对 `**` 包住, 而手滑留下的那个空格正好废掉了闭合 `**` 的 right-flanking。

### 9.3 不误伤的既有安全写法 (脚本实测通过, 勿改)

| 写法 | 为何合法 |
| --- | --- |
| `文字 **"引号内"** 文字` | 开启 `**` 左侧是空格, 但**右侧**是 `"` 非空白 → left-flanking 成立（示例只演示 flanking 位置; 写作中改用**半角引号**, 全角 `“”` 属禁用全角标点, 见 SKILL.md #3） |
| `**术语**, 说明` / `**术语**: 说明` | 闭合 `**` 左侧是"语/术"非空白 → right-flanking 成立 |

**判据只看"该 `**` 的定界方向那一侧"**: 开启看右邻, 闭合看左邻。开启 `**` 左边有空格完全没问题。

### 9.4 自动化检测 (verify_discipline.py 第 11 项, FAIL 级)

按行扫 (去 wikilink / 内联代码 / `\*\*` 转义), 给该行每个 `**` 按出现顺序编号:
- **奇数号** = 开启 → 查右邻字符, 为空白则 FAIL (`L{n}(第{k}个**右侧空白)`);
- **偶数号** = 闭合 → 查左邻字符, 为空白则 FAIL (`L{n}(第{k}个**左侧空白)`)。
- **标点邻位升级**: 邻位是**标点** (ASCII 或全角) 时再查另一侧 ——
  开启 `**` 右邻为标点 → 左邻须为 行首/空白/标点; 闭合 `**` 左邻为标点 → 右邻须为 行尾/空白/标点;
  另一侧是汉字/字母 → 同样 FAIL。案例与正写法见 9.9。

详情直接打印行号 + 序号, 逐行删掉那个空格 (或按 9.9 正写法改) 即可。

### 9.5 ⚠️ 已废弃的错误判定 (勿复用)

初版用「**行内 `**` 出现奇数次**」判定配对失衡, **完全抓不到本类 bug**:
`**可乘性 (易错点) **: ...; **乘以负数时不等号必须反向**` 里 `**` 恰好出现 **4 次 (偶数)**,
只是 flanking 错位, 奇数判定直接放行。**正确判据只有 flanking, 不看奇偶。**

### 9.6 人工排查流程 (脚本没覆盖到时)

1. Obsidian 阅读模式打开文件, 看加粗是否"前段粗、后段没粗"或"冒号后整段被粗"。
2. 切**源码模式** (Ctrl+E), 定位到该行, 给每个 `**` 从 1 开始编号。
3. 按"奇数=开启看右侧、偶数=闭合看左侧"逐个查, 找到那个**贴了空格**的 `**`。
4. 删掉那个空格, 让 `**` 紧贴 `)`。
5. 重跑 `verify_discipline.py --all <file>` 确认该项 OK。

### 9.7 批量修法 (同文件多处命中时)

一次替换即可清干净, 改完必须重跑 verifier:

```python
import re
new = re.sub(r'\) \*\*:', ')**:', raw)   # 中文右括号 + 空格 + 闭合** + 冒号
```

**先扫后改**: 改之前先按 9.4 的规则扫一遍拿到完整行号清单, 替换次数应与清单条数一致,
不一致说明有别的姿态混进来, 需逐个手工确认, 不要盲改.

### 9.8 ⚠️ `**$数学式$**` 的标点 flanking 失效 (2026-09-04 实测, 现有 verifier 未覆盖)

> 9.4 的脚本**只查空白 flanking**, 漏掉了这一类——`**$...$**` 在 Obsidian (markdown-it) 与严格 CommonMark 下**都会断裂**,
> 而 9.4 的奇偶/空白判定全部放行, 故**必须用本节的判定单独排查**。

**根因**: `**` 定界需要 left/right-flanking 成立, 而数学式以 `$` (ASCII 标点) 起止, 形成两种致命姿态:

| 姿态 | 判定 | 结果 |
| --- | --- | --- |
| **开启 `**` 紧跟 `$` 且左侧是字母** (如 `值域**$(0,+\infty)$**`, `若**$f(x)<g(x)$**`) | left-flanking 要求: 跟随标点 `$` 时, 左侧必须是标点/空白 → 左侧是字母 → **失效** | 开不了, 整段错位 |
| **闭合 `**` 紧贴 `$` 且右侧是字母** (如 `**$y=x^{-1}$**为`, `**$a^{0}=1$**则`) | right-flanking 要求: 前导标点 `$` 时, 右侧必须是标点/空白 → 右侧是字母 → **失效** | 合不上, 整段错位 |

错位后 Obsidian 表现: 该公式**没加粗**, 而它前面/后面的某个 `**xxx**` 被**错误整段加粗** (如 `,恒过` 被粗、`定点` 反而不粗)。
判定口诀: **`**` 的一边贴着 `$`, 另一边就不能是字母**——必须至少一边是标点/空白。

**正写法 (三选一, 按场景)**:
1. **把加粗目标从公式移到标签** (首选, 且符合 ### 6.1"公式本身不粗"): `值域**$(0,+\infty)$**` → `**值域**$(0,+\infty)$`; `定义域**$(0,+\infty)$**` → `**定义域**$(0,+\infty)$`。
2. **向公式一侧延伸一个相邻字** (保留公式被强调): `**$y=x^{-1}$**为` → `**$y=x^{-1}$为**`; `**$y=x^{1/2}=\sqrt{x}$**仅` → `**$y=x^{1/2}=\sqrt{x}$仅**` (延伸后闭合 `**` 落回字母上, right-flanking 成立)。
3. **用半角标点包住** (公式两侧本就缺标点时): `若**$f(x_{1})<f(x_{2})$**则` → `若,**$f(x_{1})<f(x_{2})$**,则` (逗号必须**半角且紧贴 `**`, 不可加空格**——空格会让开启 `**` 左侧变空白而再次失效)。

**批量排查**: 用 markdown-it / commonmark 逐行渲染, 比对每行 `**...**` 意图 span 是否都进了 `<strong>`; 任一未进即命中本节。
(已用此法在 `理论精讲1-数学分析1.md` 抓出 L9/L15/L21/L30 共 9 处并修复。)

### 9.9 ⚠️ 粗体以「任意标点」贴边时的 flanking 失效 (2026-09-05 实测, 9.8 的一般化)

> 9.8 只列了 `$` 一种标点, 本次实测发现**右括号 `)`、引号等一切 ASCII/全角标点**邻位同样触发,
> 且 9.4 旧脚本 (只查空白) 与 9.8 判定 (只查 `$`) 双双放行。9.4 已升级为「空白 + 标点邻位」双查 (见上)。

**统一判据 (取代 9.8 的两行表格)**:
1. **开启 `**`**: 右邻是标点时, 左邻必须是 行首/空白/标点; 左邻是汉字/字母 → 失效 (`…值域**$(0,+\infty)$**`、`…说**$x$**` 开不了);
2. **闭合 `**`**: 左邻是标点时, 右邻必须是 行尾/空白/标点; 右邻是汉字/字母 → 失效 (`$\delta$**即`、`(列数)**而非` 合不上)。

判定口诀: **`**` 的一边贴着标点, 另一边就不能是汉字/字母。**

**真实案例 (理论精讲12-高等代数4.md L13)**: `比较对象是**未知数个数$n$(列数)**而非方程个数$m$` ——
闭合 `**` 左邻是 `)`、右邻是"而", right-flanking 不成立; Obsidian / markdown-it 实测该对 `**` 整段不渲染
(用户看到的"大片加粗渲染错乱"即是此处)。另: `理论精讲4-数学分析4.md` L54 `取其中**最窄的那个$\delta$**即可通用`
同属闭合贴 `$` 右邻汉字的姿态。

**正写法 (三选一, 与 9.8 同思路)**:
1. **把贴边的括注/公式移出粗体** (首选, 兼合 ### 6.1"公式本身不粗"): `比较对象是**未知数个数$n$(列数)**而非…` → `比较对象是**未知数个数**$n$(列数),而非…`。
2. **闭合 `**` 后补半角标点** (逗号/冒号紧贴 `**`, 不加空格): `…(列数)**,而非…`。
3. **粗体尾部延伸到汉字再闭合**: `…$\delta$**即可` → `…$\delta$即可**` (仅当整段都需强调时用)。

## 10. 与脚本的分工

- `verify_discipline.py` 检查**机械可判定**的五项:
  1. **整条全粗 ≥15 字 (FAIL)** —— 整句涂色 = 没锚点;
  2. **单条加粗块 > 3 (WARN)** —— 第 4 处起删或拆; **⚠️ 脚本阈值滞后于第 4 节新值 (>60 可见字且已按 checklist #19 拆行者以 ≤5 为基准、并按整条字数浮动上调, 2026-09-29 定), 见第 4 节「脚本口径已滞后」段;**
  3. **单条加粗占比 > 40% (仅 ≥30 字的条目, WARN)** —— 整条在涂色;
  4. **单节平均加粗块 > 2.5 (仅 ≥5 条的节, WARN)** —— 说明也粗了; **⚠️ 阈值滞后于第 4 节新值 3.5, 同为已知豁免, 见第 4 节;**
  5. **加粗 `**` 的 flanking 成立 (FAIL)** —— 开启 `**` 右侧 / 闭合 `**` 左侧不得为空白;
     **且邻位是标点时须再查另一侧**(标点邻位双查, 2026-09-05 升级, 见 #9.9)—— 开启 `**` 右邻为标点
     则左邻须为 行首/空白/标点, 闭合 `**` 左邻为标点则右邻须为 行尾/空白/标点, 另一侧是汉字/字母即 FAIL。
     违反则配对错位、把中间一大段一起加粗 (本节 #9 新增; ⚠️ 初期误用"奇偶次"判定, 已废弃, 见 #9.5)。
  阈值刻意留宽 (短条目不查占比、节级只查平均值), 因为**术语清单天然"整条都是加粗"**, 收紧必然误伤。
- **语义层面** (该不该粗、粗的是术语而不是说明) 脚本查不了, 靠本文件的三问过滤 + 白/黑名单, 由我写的时候自觉遵守。
- WARN 不阻断退出码, 但必须逐条看一眼; FAIL 必须修掉才能 present。
